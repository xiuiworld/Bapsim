# A08 실측 기록

`continuous_uart.py`는 현재 A08 펌웨어가 내보내는 20Hz `A08 SAMPLE`을 COM8에서 읽는다.
SWD 디버거 연결·CPU 정지·리셋·직렬 명령 전송 없이 관측을 저장한다.
보드에는 로그 파일을 저장하지 않으며 Windows 노트북의 파일로 저장한다.

```powershell
& tools/a08_capture/start_continuous.ps1 -Until '<사용자가 정한 종료 시각>'
```

이미 실행 중인 기록기를 중복 시작하지 않는다. 현재 폴더는
`local-data/a08/current-continuous-session.txt`에 있고 그 폴더의 `status.json`으로
최신 표본 시각·수량·재연결 횟수를 확인한다.

- 날짜별 `raw.csv`: UTC 수신시각, BootId, 표본 순번, 보드 uptime, ADC 5채널, VDD, 개폐.
- 날짜별 `uart.jsonl`: 센서 진단·판정·취득 간격 및 로그 누락 경고.
- 날짜별 `events.jsonl`: USB 연결/단절과 불완전한 행 처리.
- `metadata.json`: 종료 시각, 입력 의미, 실제 식사와 구분할 사용 조건.

기록기는 USB 단절을 재시도하며 기존 파일을 덮어쓰지 않는다. 실행 중 자동 절전을
방지하지만 노트북 종료·재부팅·뚜껑 닫기에 따른 강제 절전까지 막지 않는다.
그 경우 기록 공백이 생긴다. 재로그인 후 위 명령으로 새 폴더에서 기록을 재개한다.
현재 기록 폴더에 빈 `STOP` 파일을 만들면 안전하게 종료한다.

보드 시간은 BootId가 같은 동안만 이어진다. PC 수신시각은 전송 지연을 포함한다.
순번 단절·부팅 변화·40~60ms 밖의 취득 주기는 분석에서 구분하며 누락을 복원하지 않는다.
COM8을 다른 시리얼 프로그램과 동시에 열 수 없다.

이 도구는 별도로 승인한 기록 작업에만 사용한다. 현재 개발용 PC 수집은 종료됐고 공개 준비를 위해 다시 시작하지 않는다.
자동 종료 시각은 파일 기록만 멈추며 밥솥 전원이나 보온 기능을 제어하지 않는다.
이 USB 기록은 노트북에 저장되므로 보드가 충전기만 연결된 동안은 기록하지 못한다.

초기 `run_session.py`의 SWD CSV는 기존 펌웨어용 주소를 사용한다. 새 펌웨어에서 실행하지
않는다. 10월 7일 첫 회차는 이 파일로 보존하며, 이후 연속 수집은 UART 도구만 사용한다.

사용자가 취사한 밥 대부분을 다른 밥솥으로 옮기고 이 밥솥에는 약 1인분을 남겨 보온할
예정이다. 이 회차들은 센서·운전 상태 개발용 기록이다. 개폐나 보온만으로 실제 섭취 여부,
남은 밥 양 또는 평소 식사 패턴을 확정하는 자료로 쓰지 않는다.

과거 SWD 도구 `run_session.py`는 `--serial`, `--elf`를 명시해야 한다. `--port`로 UART 포트를 지정할 수 있다. 새 펌웨어에는 과거 메모리 주소를 적용하지 않는다.
