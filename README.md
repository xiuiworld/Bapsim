# 밥심 (Bapsim)

밥솥에서 밥을 꺼내 먹는 독거노인의 사용 패턴을 관측해, 자녀의 안부 확인을 돕는 프로젝트입니다. **사람과 LLM 모두 이 README에서 시작하고, 담당 영역의 상세 문서를 읽은 뒤 작업합니다.**

## 문서가 구현의 기준입니다

합의한 요구·설계·데이터 계약을 구현의 기준으로 둡니다. 코드가 문서와 다르다고 문서를 조용히 코드에 맞추거나, 이전 대화의 추측으로 현재 합의를 바꾸지 않습니다. 불일치를 발견하면 원인과 영향부터 확인합니다. 새로운 합의가 필요한 변경은 합의표와 관련 상세 문서에 반영하고 코드·예시도 함께 맞춥니다.

README는 목적·현재 상태·읽는 순서를 안내합니다. 정책의 자세한 수치와 필드는 아래 담당 문서에서 관리합니다. 인터뷰는 결정 배경을 보존한 기록이며, 과거 발언과 충돌하면 후속 합의가 반영된 현재 설계 문서를 따릅니다. 문서에 적힌 ‘설계 합의’와 ‘실제로 검증된 동작’을 구분합니다.

## 현재 상태

2026-10-02 팀 합의를 반영했습니다. HA 수신 이후의 정규화·개인화·알림 코드와 가상 입력 시험 경로가 있으며 [현재 구현 상태](docs/IMPLEMENTATION_STATUS.md)에 확인 범위를 기록합니다. 센서 배선, Matter 실물 등록·수신, AI의 실제 생활 데이터 성능, 실제 휴대폰 알림은 미검증입니다. 공동 저장소는 `xiuiworld/Bapsim`으로 관리합니다. GitHub 공유 상태와 구현 완료 여부는 별개입니다.

- 대상은 밥솥에서 밥을 꺼내 먹는 사람입니다. 소분·냉동 보관을 주로 하는 생활은 이번 범위에서 제외합니다.
- 개방은 식사 가능 행동의 단서입니다. 식사 완료·섭취량·질병·사망·안전 여부를 확정하지 않습니다.
- Edge AI와 Google Home·HA Multi-Admin은 구현 목표입니다. 보조 기기는 실제 추가 없이 가상 입력으로만 검증합니다.
- 센서는 10월 6일 발송 예정으로 전달받았습니다. 실제 수령·설치 완료를 확인한 것은 아닙니다.
- 코드까지 공개하는 방향에 합의했습니다. 비밀·개인정보·라이선스 검토와 실제 공개는 후속 작업입니다.

## 시스템과 역할

```text
밥솥 + 외부 센서 + 보드 Edge AI
    → Matter over Thread → Nest Hub 2세대 → 가정 IP 네트워크
    → HA / Matter Server → 밥심 분석 서비스
    → HA 화면·알림 → 자녀 휴대폰의 Companion 앱
```

Nest는 Thread 연결을 중계합니다. 같은 밥심 보드를 Google Home과 HA에 각각 등록하며, Google Home에 저장된 값을 HA로 복사하는 구조가 아닙니다. 보드는 밥솥의 관측·상태 추정, 노트북은 개인별 사용 패턴과 알림 판단을 담당합니다. 제조사 API와 원격 취사 제어는 사용하지 않습니다.

| 담당 | 책임 |
|---|---|
| A · 하드웨어 담당 팀원 | 센서·펌웨어·보드 Edge AI 학습/배포·Matter·HA/Matter Server·네트워크·실기 통합 |
| B · 소프트웨어 담당 사용자 | HA 수집/정규화/저장·개인 패턴 학습·가상 보조 입력·폰 화면·알림·확인/보류 조작 |

장비는 A에게 있으며 B는 원격으로 개발합니다. A 노트북은 팀의 기존 기록상 Galaxy Book3 Pro / Windows 10 Pro입니다. HA OS VM과 공식 Matter Server 방향을 채택했고 실제 네트워크 구성은 확인 전입니다. B는 모델과 실행 코드를 Docker 이미지로 전달합니다. 분석 결과 상태는 로컬 MQTT로 HA에 반환하고, 알림은 HA 서비스를 호출합니다. 외부 접속은 HA Cloud 무료 체험을 사용하기로 했으며 체험 시작은 아직 하지 않았습니다.

## 장비와 관측 범위

확정 밥솥은 **CUCKOO CRP-G1020MP**, 보드는 **nRF54LM20-DK**, Thread Border Router는 **Nest Hub 2세대**입니다. 자석 개폐센서·NTC 온도센서·GL5528 광센서를 사용합니다. 광센서는 구매 5개 중 잠김·보온·백미·상단 맨 왼쪽 시간 LED에 4개, 예비로 1개를 배정했습니다.

시간 LED는 ‘예약 2시간 / 찜 10분’ 공유 표시입니다. 단일 LED로 전체 예약 여부·남은 시간을 확정하지 않으며 예약 관련 추정은 가능한 범위에서 검토합니다. 온도는 설치 지점의 값입니다. 부착 위치·보정·내열/증기 조건과 LED 의미는 실기 검증 대상입니다. 부품별 수량·구매 링크와 설명서의 모델 차이는 [하드웨어 안내](docs/hardware/README.md)에 있습니다.

## 핵심 서비스 합의

- 개방은 첫 개방부터 60분 고정 창으로 묶고 추가 개방으로 연장하지 않습니다. 원 개방 기록도 보존합니다.
- 개인별 사용 시간대·간격·요일 차이를 배우며 약 일주일 초기 학습 후 계속 보정합니다. 기록이 부족하면 학습 완료로 보지 않습니다.
- 생활 변화 안내는 연속 사용 공백과 며칠간 사용 감소의 두 종류입니다. 규칙형은 두 예상 사용 창 연속 미관측, 불규칙형은 개인 간격을 기준으로 합니다. 실제 두 끼 결식 판정은 아닙니다.
- 확인 버튼·여행 기간 알림 쉬기·야간 보류를 포함합니다. 보류 종료 시 재평가하고 여행 구간을 정상 학습에서 구분합니다.
- 기록 보존은 정규화 관측 90일, 행동·기준·판단·발송 180일입니다. 세부 정책과 조정 가능한 후보 수치는 아래 정책 문서가 기준입니다.
