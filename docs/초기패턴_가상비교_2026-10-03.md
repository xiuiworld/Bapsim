# 초기 사용 패턴 입력의 가상 비교

`python -m ai.initial_routine_experiment`로 같은 가상 밥솥 사용 기록을 초기 시간·요일 입력 **없음**과 **있음**에 각각 재생했다. 보호자 발송 요청까지 실제 `PersonalUsageModel`과 `DetectionStateManager`를 통과시켰다. 코드를 확인하던 중 다른 시간대의 `learning` 판정이 이미 쌓인 알림 후보를 지우는 문제를 발견해 수정했다. 연결 단절의 `data_unavailable` 판정은 계속 후보를 지운다.

각 가구는 첫 5일 동안 사용 기록을 쌓고 다음 14일을 평가한다. 두 번의 2일 연속 사용 중단을 스크립트로 넣었다. 정확한 매일 아침 사용, 평일 외부 점심, 점심 요일 오입력, 아침 시각 오입력(실제 17시·입력 8시), 요일 오입력, 불규칙 건너뜀의 6조건을 둔다. 외출 1일과 통신 단절 1일은 평가에서 제외한다. 난수 시드를 달리한 개발 24가구와 별도 재현 24가구를 사용했으며, 각 비교 쌍의 사용·중단·외출·단절은 같다. 기준 확률이나 알림 임계값은 이 실험으로 조정하지 않았다.

| 별도 재현 24가구, 14일 | 초기 입력 없음 | 초기 입력 있음 |
| --- | ---: | ---: |
| 중단 사건 포착 | 0/48 | 33/48 |
| 첫 7일의 사건 포착 | 0/24 | 14/24 |
| 정상일 알림 요청 | 1 | 1 |
| 외출·단절일 알림 요청 | 0 | 0 |
| 포착 사건의 첫 요청 중앙 지연 | 해당 없음 | 26.02시간 |

초기 입력을 한 그룹은 정확한 매일 아침과 주말 점심 입력 조건에서 각각 8/8건을 포착했다. 시각이 크게 틀린 조건은 0/8건이며, 요일이 틀린 조건은 4/8건, 불규칙 건너뜀은 5/8건이다. 평일 점심을 잘못 입력한 조건도 8/8건이었지만, 이 좁은 생성 규칙만으로 불필요한 알림 위험이 없다고 결론낼 수 없다. [전체 결과](../ai/initial_routine_result.json)에 조건별 수치를 남겼다.

이 실험은 초기 학습 기간 중 발생한 중단을 의도적으로 포함한다. 그래서 초기 입력의 조기 판정 효과가 두드러진다. 모든 중단과 정상 사용을 같은 생성 규칙으로 만들었고 실제 생활의 분포, 실제 식사, 위험 상태, 센서 누락률을 추정하지 않았다. 가상 실험의 33/48을 현장 정확도로 사용해서는 안 된다. 초기 입력이 오래되거나 틀릴 수 있으므로 실제 적용 시에는 수정·해제 경로와 보호자 확인을 유지해야 한다.
