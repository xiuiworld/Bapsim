# 밥심 문서·구현 대조 점검

후속 기록: 실물 연결 대비 작업에서 HA 취사 상태 엔티티 매핑 서비스와 두 입력 가용성 진단을 추가했다. 상호운용성 검토 후에는 타 Matter 기기의 선택적 원시 입력 경로도 추가했다. 아래의 41개 테스트 및 ‘취사 어댑터 미구현’·‘타 기기 미구현’ 표기는 이 점검 당시의 기록이다. 최신 상태는 [구현 상태](IMPLEMENTATION_STATUS.md), [상호운용성 구조](Matter_상호운용성_구조.md), [실물 연결 가이드](실물_밥솥_연결_가이드.md)를 따른다.

2026년 10월 2일 기준

## 기준과 범위

- 현재 구조와 구현 순서는 [HA·AI·Matter 컨텍스트 요약](reference/밥심_HA_AI_Matter_컨텍스트_요약.md)을 기준으로 확인했다.
- [Matter 구현 보고서 초안](reference/밥심_Matter_구현_보고서_초안.pdf)은 기획 배경이다. 그 문서의 보드 내부 분석·Matter 결과 송신 구조는 현재 팀 분업의 구현 기준이 아니다.
- Nordic 펌웨어는 다른 담당자의 범위다. 타 Matter 기기의 생활 맥락 결합은 사용자 결정에 따라 이번 구현 범위에서 제외하고, 밥솥 판정 뒤의 확장 경계만 유지한다.

## 현재 도달점

**밥솥 데이터 분석 소프트웨어 초안과 로컬 Home Assistant 시연 환경은 구현됐다. 실제 Matter 밥솥 센서에서 보호자 휴대폰까지 이어지는 통합 시연은 아직 완료되지 않았다.**

| 영역 | 코드/설정 | 확인한 수준 | 남은 일 |
| --- | --- | --- | --- |
| Home Assistant 기반·시뮬레이터 | 있음 | 로컬 컨테이너 실행, 설정 검사, 8개 원시 입력 버튼 | 실제 장비 환경에서 재확인 |
| 원시 이벤트 계약·정규화 | 있음 | 8필드 계약, 상태 전이·2초 접점 확인·단절 처리 자동 테스트 | 실제 Matter 입력 시각·값 검증 |
| 취사 세션·24시간 특징 | 있음 | 순수 Python 자동 테스트 | 실제 취사 시작·완료 입력원 연결 |
| 개인 기준·초기 판정 | 있음 | 7일 학습 조건과 규칙 자동 테스트 | 실제 7일 이상 생활 데이터 및 오경보 평가 |

## 구현 범위에서 주의할 차이

1. **접점만으로 핵심 취사·개방 괴리를 검증할 수 없다.** 현재 Matter 어댑터는 뚜껑 접점과 통신 상태를 원시 이벤트로 바꾼다. 취사 시작·완료 이벤트는 변환하지 않는다. 세션 빌더는 취사 세션이 없는 뚜껑 열림을 세지 않으므로, 실제 접점 센서 하나만 연결하면 취사 후 첫 개방 지연과 취사 대비 개방 감소를 계산할 수 없다. 하드웨어/입력 인터페이스에서 취사 상태를 어떻게 받을지 합의가 필요하다.
2. **Colab 비교 기준은 운영 규칙 실행으로 수정했다.** 노트북에 현재 `RuleDetector` 소스를 포함하고 합성 비율을 기준 특징으로 변환해 비교한다. 후보 가중치는 HA에 적용되지 않았으며, 합성 비교 결과를 실제 가구 성능으로 해석하지 않는다.
3. **자동 연결 검증을 추가했다.** 원시 입력 → 코어 판정 → 알림 요청·응답을 한 테스트로, HA 이벤트·로컬 알림 서비스를 가짜 HA 환경에서 별도 테스트로 확인한다. 실제 HA 서버의 이상 알림 전체 흐름, 실물 Matter 수신, 보호자 푸시 수신은 아직 검증하지 않았다.
4. **화면 응답 대상은 활성 사건으로 수정했다.** 사건이 하나면 시뮬레이터·Matter 출처 모두 버튼이 그 사건에 응답한다. 여러 사건이 동시에 있으면 출처와 기기 ID를 명시한 서비스 호출이 필요하다. 실물 화면 시험은 남았다.

## 문서 해석

- 컨텍스트 요약에 있는 타 Matter 기기 등록·융합·ablation과 제조사 API, 보드 측 구현은 현재 완성 목록이 아니다. 타 기기 연계는 의도적으로 보류했다.
- 오래된 PDF의 보드에서 분석 후 결과를 Matter로 송신하는 순서는 현재 HA 수신 이후 분석 구조와 다르다. 현재 코드가 PDF의 보드 분석·전용 클러스터·Matter 송신을 구현했다고 주장하지 않는다.
- 합성 데이터 결과는 정의한 가상 상황의 비교 결과다. 실제 식사·건강 상태 판별 성능을 뜻하지 않는다.

## 이번 점검의 근거

- 프로젝트 문서 전체, Python 구현, Home Assistant 설정·대시보드·서비스 파일, 41개 테스트를 대조했다.
- `python -m unittest discover -s tests -q`: **41개 통과**. 취사 직후 첫 개방 대기 처리와 Matter 접점 초기 상태 수신을 추가 확인했다.
- 실행 중인 Home Assistant의 `check_config`: **통과**. 컨테이너 로그에 이번 재시작의 통합 오류는 없고, 커스텀 통합에 대한 HA의 일반 경고만 확인했다.

## 다음 검증 순서

1. Nordic 팀과 **뚜껑 상태 외 취사 시작·완료를 어떤 입력으로 받을지** 결정한다. 취사 이벤트가 없다면 탐지 범위를 뚜껑 행동 중심으로 다시 정의해야 한다. [입력 연계 계약](밥솥_Matter_입력_연계_계약.md)에 필요한 값을 적었다.
2. 실물 Matter 접점을 HA에 등록해 `on/off` 방향, 시간, 단절·복구를 확인한다.
3. 실제 입력으로 판정과 로컬 알림을 재현하고, Matter 사건의 보호자 응답 화면을 현물 환경에서 확인한다.
4. 보호자 휴대폰 등록 후 셀룰러 수신과 응답을 검증한다.
5. Colab의 운영 규칙·후보식 비교를 실제 데이터로 재평가한 뒤에만 후보식 적용 여부를 결정한다.
