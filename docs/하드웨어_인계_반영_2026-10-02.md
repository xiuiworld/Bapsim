# 하드웨어 인계 반영 및 통합 준비

작성 기준: 2026-10-02. 하드웨어 담당 인계 문서와 이 저장소의 구현을 대조한 기록이다. 구매·설계·실측 성공을 구분한다.

후속 사용자 제공 [시스템 아키텍처 v0.2](reference/밥심_시스템_아키텍처_v0.2.md)에서는 밥솥을 쿠쿠 CRP-G1020MP로, Thread Border Router를 구글 네스트 허브 2세대 구매로 명시하고 Edge AI·Multi-Admin을 설계 목표에 포함했다. 아래 인계 당시의 ‘네트워크 장비 미확정’은 이 후속 결정으로 갱신해 읽는다. 네스트 구매와 실물 Thread·Matter 연결 성공은 별개다.

## 역할과 현재 도달점

- 하드웨어 담당: 보유 밥솥에 센서를 부착하고 nRF54LM20-DK(PCA10184, 리비전 0.7.0)에서 측정, 실제 Matter 노출, commissioning 가능한 장치와 측정 로그를 제공한다. 보드는 1대 확보했고 센서·연결 부품은 구매했다. 배선·플래시·Matter 수신 성공은 아직 확인되지 않았다.
- HA 담당(이 저장소): HA 수신 이후 원시 어댑터, 정규화, 세션, 특징, 개인 기준, 판정, 알림, 대시보드와 합성 실험을 맡는다. 로컬 HA 시뮬레이터와 Python 코어는 구현되어 있으나 실물 Matter와 보호자 휴대폰 수신은 미검증이다.
- 현재 구현에서 타 Matter 기기의 생활 맥락 결합은 보류했다. 밥솥 단독 경로가 우선이며 타 기기 부재를 활동 0으로 해석하지 않는다.

## 실물 센서 구성과 해석 경계

| 관측 대상 | 계획된 센서 | 지금 말할 수 있는 값 | 분석에 쓰기 전 확인할 것 |
| --- | --- | --- | --- |
| 실제 뚜껑 | 5C-39 NO 자석 접점 | 접점 전이 | 부착 위치와 열림/닫힘 극성, 흔들림, HA 상태 방향 |
| 열림/잠김 표시 LED | GL5528 | 밝기 또는 점등 변화 | 실제 표시 의미. 잠금 해제와 뚜껑 개방은 별개 |
| 보온 표시 LED | GL5528 | 밝기 또는 점등 변화 | 선택/대기/실행/취사 완료 중 무엇을 뜻하는지 |
| 백미 표시 LED | GL5528 | 밝기 또는 점등 변화 | 메뉴 선택과 실제 취사 진행을 구분할 수 있는지 |
| 설치 지점 온도 | NTC 10K B3950 VLT-THS010 | 해당 지점의 온도 변화 | 설치 위치, 변환·오류, 허용 온도·증기·방수 조건 |

광센서는 5개 구매했고 3개 부착·2개 예비다. 10kΩ 저항은 20개 구매했다. 이 수량은 동작 검증이 아니다. 온도센서는 유지하기로 했으나 케이블·밀봉부의 내열 및 수증기 내구성은 확인되지 않았다. Thread Border Router 또는 Wi-Fi 확장 장비의 최종 확보 상태도 미확인이다.

현재 소프트웨어의 `cooking_state=started/finished`는 **확인된 실제 취사 전이**가 들어올 때만 유효하다. 백미 LED 점등, 보온 LED 점등, 온도 상승, 잠금 LED 변화 하나로 시작·완료를 생성하지 않는다. 취사 완료 시각을 확보하지 못하면 `first_open_delay_min`과 취사·개방 괴리의 실물 성과를 계산하거나 주장하지 않는다. 뚜껑 접점만으로도 관측·전달·방향 검증은 가능하지만 현 세션·특징·판정 경로의 전체 성능 검증은 아니다.

## 인계받아 기록할 실제 인터페이스

각 센서에 대해 다음을 한 행씩 채운다. LED·온도는 Matter 노출 방식이 확정되기 전까지 HA 서비스에 억지로 등록하지 않는다.

| 항목 | 기록할 값 |
| --- | --- |
| 식별 | 논리적 `device_id`, 센서명, Matter endpoint/cluster/attribute, HA entity ID |
| 값 의미 | 센서 원시값, Matter 값, HA 표시값, 실제 동작의 대응표. 접점의 `on_is_open` 방향 |
| 유효성 | 정상, 미확정, 센서 오류, 연결 단절, 미지원 상태의 실제 표시값 |
| 시간 | 보드 관측 시각 제공 여부, HA 수신 시각, 갱신·보고 정책, 재연결 시 초기값 |
| 취사 | 시작·완료의 실측 근거와 HA의 정확한 상태값. 구별 불가하면 `미지원`으로 기록 |
| 재현 | 펌웨어/SDK 버전, commissioning 절차, 조작별 로그, 재부팅·단절·복구 결과 |

HA 수신 시각을 보드 측 측정 시각으로 표기하지 않는다. 보고가 없다는 사실만으로 장치 오프라인이나 활동 없음으로 판정하지 않는다. 일부 센서의 오류를 숫자 0이나 `false`로 채우지 않는다. 원시 입력은 기존 [8필드 계약](../inputs/base/contracts.py)을 거쳐 정규화기로 보낸다. 향후 LED·온도 어댑터가 필요하면 그 센서의 관측값을 원시 이벤트로 먼저 보존하고, 검증된 해석 규칙을 정규화 이후에 둔다.

## 다음 공동 실험 순서

1. 보드와 네트워크 구성, 실제 HA 호스트, Matter 수신 경로를 확정하고 장치·버전을 기록한다.
2. 뚜껑 접점 한 신호를 Matter로 보내 HA entity → `bapsim_raw_event`의 극성과 시각을 대조한다. 취사 입력 미등록 상태에서는 원시 접점값을 `availability=offline`으로 기록하고 행동 이벤트는 보류한다. 취사 입력까지 검증·등록되면 `bapsim_cooker_event`를 대조한다. 실제 commissioning과 수신 로그가 완료 증거다.
3. 메뉴 선택만 함, 실제 취사 중, 취사 완료/보온 전환, 잠금 변경, 뚜껑 개방, 주변 조명 변화, 단절·복구를 각각 사람의 시각 기록과 센서·HA 로그로 대조한다.
4. 시작·완료를 안정적으로 구분하는 근거가 있으면 그때 정확한 HA 상태값을 등록한다. 없으면 취사 기반 지표를 실물 검증 범위에서 제외하고 뚜껑 관측 중심의 시연 범위를 명시한다.
5. 원시 수신, 밥심 판정, 로컬 알림, 보호자 휴대폰 셀룰러 수신·응답을 각각 별도로 검증한다.

현재 공개 시연의 목표일은 2026-10-15로 전달받았다. 위 항목 가운데 장비·동작 로그가 없는 부분은 구현 완료로 표시하지 않는다.

심사표의 다섯 항목별 실물 증거와 Multi-Admin 시험은 [하드웨어 심사 대비 실물 검증표](하드웨어_심사_실물_검증표.md)에 정리했다.
