# 하드웨어 심사 대비 실물 검증표

기준: 2026-10-02. 심사표의 다섯 평가 항목을 실제 장비의 완료 증거로 연결한다. 이 문서는 시험 계획이며, 빈칸이나 `미검증`은 성공을 뜻하지 않는다. Nordic 펌웨어·센서 부착은 하드웨어 담당, Home Assistant(HA) 수신 이후는 밥심 담당의 범위다. 실제 결과는 [실물 수신 기록](실물_Matter_수신_검증_기록.md)에 남긴다.

## 먼저 확보할 증거

| 순서 | 실물 시험 | 통과 증거 | 현재 상태 |
| --- | --- | --- | --- |
| 1 | 뚜껑 접점 → Matter → HA | 페어링 정보, endpoint/cluster/attribute, 실제 열림·닫힘의 HA 값과 `bapsim_raw_event` 시각 | 미검증 |
| 2 | 취사 시작·완료 구별 | 메뉴 선택만 함, 취사 시작, 취소, 완료·보온 전환의 사람 기록과 각 센서·HA 값 대조. 두 상태가 구별될 때만 등록 | 미검증 |
| 3 | 연결 안정성 | 재부팅, 센서·네트워크 단절, 복구, HA 재시작 후 상태 및 중복 이벤트 확인 | 미검증 |
| 4 | 다른 Controller와 공유 | 첫 Controller에 연결한 뒤 Multi-Admin으로 두 번째 Controller에 추가하고 같은 접점 변화를 양쪽에서 확인 | 미검증 |
| 5 | 설치·내구 | 부착 위치, 고정 방식, 열·증기 노출, 반복 사용 후 센서 값과 배선 상태 기록 | 미검증 |

취사 시작·완료를 안정적으로 구별하지 못하면 `started_state`/`finished_state`를 임의로 지정하지 않는다. 이 경우 실물 시연은 접점 관측·Matter 연동으로 제한하고, 취사 후 첫 개방 지연과 취사·개방 괴리를 실물 성과로 제시하지 않는다. LED 점등이나 온도 상승 하나만으로 취사 전이를 만들지 않는다.

## 평가 항목별 입증 자료

| 평가 항목 | 보여줄 실물 증거 | 판정 시 주의할 점 |
| --- | --- | --- |
| Matter 구현 완성도 (30) | 보드·펌웨어·SDK 버전, 전송 방식/네트워크 구성, QR/페어링 절차, HA Matter 엔티티, 실제 조작별 상태 로그, 재부팅·단절·복구 기록 | 페어링 성공, 센서 정확성, 안정성은 각각 별도 확인. `sensor.bapsim_matter_input=ready`는 물리 센서 검증 완료가 아님 |
| 상호운용성 (20) | 두 Controller의 식별 정보, Multi-Admin 추가 절차, 양쪽의 동일 접점 상태와 동시각 기록, 한쪽 재시작·연결 해제 후 결과 | 두 번째 Controller에 단순 재페어링한 결과를 Multi-Admin 성공으로 기록하지 않음 |
| 온디바이스 AI/AX 활용성 (20) | 네트워크/클라우드 구성도, 외부망 차단 상태에서 센서→로컬 Matter→HA 동작 기록, HA가 생성한 생활 루틴 판정과 사용자 화면 | 현재 분석은 HA 측이다. 보드 내부 AI가 실행됐다고 표현하지 않음. 클라우드 비의존성과 온디바이스 AI는 다른 주장 |
| 창의성·문제해결성 (15) | 기존 밥솥 무개조 부착 사진, 센서별 관측 의미, 메뉴 선택·보온·잔열·잠금 표시가 취사/개방과 혼동되는 반례 실험 | 관측 신호와 추정한 행동을 분리해 설명 |
| 사업화·기여도 (15) | 부품 원가표, 장착 시간, 고정·분리 절차, 케이스/배선 사진, 반복 설치와 열·증기 내구 기록, 재현 가능한 펌웨어·설치 문서 | 부품 구매와 실제 내구·양산 가능성은 구분 |

## 연결 당일 기록 형식

각 조작을 한 행으로 기록한다. 센서 측 관측 시각을 제공하지 않으면 `미제공`이라고 쓰고 HA 수신 시각과 혼동하지 않는다.

| 날짜·조작 | 사람의 실제 관찰 | 센서 원시값 | Matter 값·endpoint/cluster/attribute | Controller 1 / Controller 2 값 | HA entity 값·시각 | `bapsim_raw_event` 값·시각 | 결과·로그/사진 파일 |
| --- | --- | --- | --- | --- | --- | --- | --- |
|  |  |  |  |  |  |  | 미실행 |

최소 조작: 뚜껑 닫힘→열림→닫힘, 접점 흔들림, 메뉴만 선택, 취사 시작, 취사 취소, 취사 완료·보온 전환, 잠금 표시만 변경, 주변 조명 변화, 전원/Thread 단절·복구, 보드/HA 재시작. 각 상태가 실제로 무엇을 뜻하는지 확인될 때까지 원시값으로 보존한다.

## HA 수신 진단

`sensor.bapsim_matter_input`의 `devices` 속성은 등록된 뚜껑·취사 엔티티 ID와 현재 HA 상태값을 보여준다. `state_unmapped`는 접점값이 `on/off`와 맞지 않는 경우이고, `connection_unverified`는 Matter uptime/snapshot의 새 보고가 없거나 3분을 넘긴 경우다. 연결 보고와 접점이 유효하고 취사 입력만 없으면 `lid_only_ready`로 접점 학습을 유지한다. 취사 엔티티가 `keep_warm`, `standby`, `cancelled` 같은 미등록 값을 내면 `partial_state_unmapped`로 표시하고 취사 기반 지표만 보류한다. 알 수 없는 값을 취사 완료로 바꾸지 않는다. 진단에 나온 HA 값만으로 센서의 물리적 의미가 검증되지는 않는다.
