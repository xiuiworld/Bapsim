# 개인 사용 패턴 평가 기록 규약

상태: 소프트웨어 평가용 v1. 실기기 성능이나 실제 식사 여부를 검증한 자료는 아직 없다. 운영 알림 설정을 바꾸지 않는다.

## 1. 기록의 단위와 경계

입력은 두 JSONL 파일로 분리한다. `observations.jsonl`은 HA 수신 이후 정규화된 관측이고, `labels.jsonl`은 관측·모델 점수와 독립적으로 정한 **가구·밥솥·KST 날짜별 확인 필요 여부**다. 이 라벨은 식사, 건강, 안전의 정답이 아니다. 이름·주소·전화번호는 넣지 않고 가명 `household_id`와 `device_id`를 사용한다. 파일은 로컬 `local-data/`에 두며 Git에 올리지 않는다.

관측 한 줄의 필수 필드:

| 필드 | 값 / 의미 |
|---|---|
| `schema_version` | 정수 `1` |
| `mode` | `simulation`, `live`, `replay` 중 하나. 모델과 결과는 서로 섞지 않는다 |
| `household_id`, `device_id` | 공백 없는 가명 ID |
| `source` | 시뮬레이션은 `simulator`; 실측은 실제 입력 출처. 재생은 원 출처를 유지 |
| `observed_at` | 시간대가 있는 ISO 8601 시각. 평가 날짜는 KST로 계산 |
| `event_type` | `device_online`, `device_offline`, `lid_opened`, `away_state` |
| `availability` | 연결·뚜껑 사건은 `online`/`offline`. `away_state`에는 대신 boolean `away` |

`device_online`은 연결이 확인된 시점에 반복 기록하는 **heartbeat**로도 사용한다. 평가에서는 연결 확인 간격이 90분을 넘거나 그날 offline·외출이 있으면 그 가구·날을 제외한다. 90분은 평가 자료의 보수적인 기본값이며 HA가 실제로 연결을 확인했다는 근거가 없는 시간에 heartbeat를 만들어 넣어서는 안 된다. 기존 정규화 관측 JSONL은 변경 시점 위주로 저장되므로 그대로는 하루 전체의 연결 증거가 충분하지 않을 수 있다. 기존 기록을 변환할 때도 `mode`·가명 ID와 검증된 연결 기록을 별도로 결합해야 한다. 누락 구간은 공백으로 남긴다.

라벨 한 줄의 필수 필드는 같은 `schema_version`, `mode`, 가명 ID, `source`와 다음 필드다.

| 필드 | 값 / 의미 |
|---|---|
| `local_date` | `YYYY-MM-DD`, KST 날짜 |
| `review` | `check_needed`, `no_check_needed`, `unknown` |
| `basis` | 가상 라벨은 `scripted_scenario`; 실제 기록은 `user_confirmed` 또는 `caregiver_confirmed`; 미확인은 `unreviewed` |

`check_needed`는 별도 확인 결과 그날 안부 확인이 필요했다고 판단한 경우다. `no_check_needed`는 확인한 결과 별도 안부 확인이 필요하지 않았던 경우다. 답변이 없거나 확인하지 못했다면 `unknown`이다. **알림이 없었다는 사실, 뚜껑을 열었다는 사실, 외출·단절 자체를 정답 라벨로 변환하지 않는다.** 외출·단절·연결 증거 부족·미확인 날짜는 TP/FP/FN/TN에서 제외하고 사유와 건수를 기록한다. 실제 라벨을 만들 때는 확인 주체와 판정 절차를 합의해 별도 보관하고, 자유 서술 메모나 민감한 사유는 이 파일에 넣지 않는다.

실제 검토에서는 알림이 나온 날짜만 확인하면 오경보·누락 비교가 치우친다. **알림이 없었던 날짜도 같은 질문과 절차로 확인**하고, 검토자는 가능하면 모델 후보를 보지 않은 상태에서 라벨을 정한다. 확인하지 않은 날짜는 `unknown`으로 유지한다.

## 2. 시간 순서 평가

`--evaluation-start` 이전 최소 21일을 이력으로 처리한다. 모델은 각 가구의 관측만 시각 순서대로 읽으며 이후 날짜를 과거 학습에 사용하지 않는다. 하루 02:30·10:30·15:30·21:30(KST)에 현재 모델의 사용 창, 불규칙 간격, 감소 경로를 오프라인으로 평가하고, 마지막 개방 후 24시간 기준과 같은 날짜에 비교한다. 현재 운영 환경의 분 단위 평가나 보호자 발송·전화 확인을 재현한 수치는 아니다. 보고서의 `personal_candidate`는 **내부 확인 필요 후보**이며 `notification_request`는 현재 상태 관리 규칙을 재생했을 때의 **발송 요청**이다. 방해금지·휴대폰 서비스·사용자 확인을 재생하지 않으므로 실제 도착한 푸시 수와 다르다.

`TP/FP/FN/TN`과 정밀도·누락 포착률·정상일 오경보율·정확도를 후보, 발송 요청, 고정 24시간 기준마다 별도로 낸다. 정확도는 정상일과 확인 필요일의 비율에 크게 좌우되므로 숫자 하나로 모델을 고르지 않는다. 가상 예시에서는 발송 요청 규칙을 거치면 오경보가 줄지만 첫 공백일의 요청이 늦어져 누락도 늘어난다. 이것은 설계한 날짜별 라벨과 보수적 안내 정책의 차이이며 실생활 성능 향상의 근거가 아니다.

보류 날짜를 줄이려고 미래 시각이나 실측되지 않은 연결 시간을 채우지 않는다. 후보 선택·설정 변경도 이 스크립트에서 하지 않는다. 실제 기록이 쌓이면 가구와 시간을 분리한 별도 보류 평가로 확인한다.

## 3. 로컬 시뮬레이터 검증

저장소 루트에서 실행한다. 아래 생성기는 두 가상 가구의 35일 기록을 만들고, 뒤 14일의 시나리오 라벨을 별도 파일에 쓴다. 연결 heartbeat, 자연스러운 건너뜀, 의도적 공백, 외출, 단절을 포함한다. `local-data/`는 Git 제외 경로다.

```powershell
python -m ai.demo_usage_records --output-dir local-data/usage-demo
python -m ai.usage_record_pipeline --observations local-data/usage-demo/observations.jsonl --labels local-data/usage-demo/labels.jsonl --evaluation-start 2026-01-26 --output local-data/usage-demo/manual-report.json
```

`report.json`과 `manual-report.json`의 `days`에서 각 날짜의 `review`, 후보, `abstain_reason`을 확인한다. 같은 파일명을 다시 쓰면 덮어쓰지 않고 실패하므로 새 디렉터리나 출력 파일명을 고른다. 이는 가상 상황에 대한 기능 시험이다.

실제 데이터를 시험할 때도 동일한 스키마의 두 JSONL을 로컬에 준비하고 두 번째 명령의 경로와 시작 날짜만 바꾼다. Colab 업로드나 운영 정책 반영은 별도 검토가 끝난 뒤 진행한다. 실물 Matter 연결과 센서 정확도는 하드웨어 담당자의 별도 검증 항목이다.
