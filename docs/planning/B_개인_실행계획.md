# B 개인 실행계획 — HA 수집·개인 패턴·화면·알림

작성·진행 상태 갱신: 2026-10-08. A는 현재 사용자, B는 원격 팀원이다. [A 개인 실행계획](A_개인_실행계획.md)과 같은 형식으로 B 담당 결과와 남은 일을 추적한다. **B가 실제로 이 순서대로 개발했다는 기록이 아니라, 현재 코드·테스트·합의 문서·현장 기록을 작업 단위로 재구성한 계획**이다. 코드 작성자를 추정하지 않고 B 책임 범위의 결과물을 정리한다.

현재 서비스의 소프트웨어 기반과 개발용 보드→HA→B→폰 연결은 확인됐다. 2026-10-08 A가 휴대폰 모바일 데이터로 HA 앱에 접속해 문 닫힘·온도 33.6°C를 확인했다. 외부망 상태 조회는 확인됐으나 외부망 푸시·상세·응답은 별도다. 실제 개인 사용 패턴의 학습·성능, 운영 판단에 따른 폰 조작과 장시간 복구까지 완료된 것은 아니다. 발표는 10월 15일 13시, A의 센서 기록 종료 예정은 10월 14일 12시(KST)다.

## 1. 목표와 담당 경계

B의 목표는 HA가 받은 관측을 검증·정규화·저장하고, 개인별 밥솥 사용 변화에 대한 근거와 확인 안내를 보호자에게 제공하는 것이다. 밥솥 개방을 실제 식사·건강 상태의 확정 증거로 해석하지 않는다.

```text
A: 센서 → 보드 관측·상태 추정 → Matter/Thread → HA 수신
                                                               ↓ 인계
B: 출처 검증 → 원시 이벤트 → 정규화·기록 → 개인 패턴 → 화면·알림·응답
A+B: 현장 조작 → 수신/판단/발송/폰 도착 대조 → 오류 재현·수정
```

| 작업 | B가 할 일 | A에게 받거나 요청할 것 |
|---|---|---|
| 입력 | HA 매핑·출처·품질·신선도 검사, 내부 계약 변환 | 실제 entity/경로·단위·극성·지원 범위 |
| 데이터 | 관측·사용·판단·발송·응답 기록과 보존/복원 | 실제 조작 시각·연결 상태·익명 실측 자료 |
| 분석 | 개인 사용 창·간격·장기 감소·생활 맥락 | 대상 사용 방식, 실측과 시험의 구분 |
| 서비스 | HA 내부 분석·선택적 독립 모드·배포 자료 | 설치 환경·기동/로그·현장 실패 증거 |
| 보호자 | 화면·알림·확인·기간 보류·취소·만료 | 폰 수신/클릭/조작·외부망 현장 시험 |
| 발표 | 합성 평가·근거·한계·복구 절차 설명 | 장치·Matter·보드 AI 증거와 버전 조합 |

현재 기본 경로는 HA 내부 분석이다. 독립 작업자 모드는 선택 사항이며 양쪽을 동시에 운영하지 않는다. 입력 어댑터와 시뮬레이터는 원시값만 전달하며 `inputs/base/contracts.py`의 경계를 유지한다. 센서·펌웨어·보드 AI는 A 담당이고, 이 계획 작성으로 제품 코드나 `firmware/`를 바꾸지 않는다.

- `[x]`는 문장에 적힌 범위의 근거가 있는 완료다. 소프트웨어 테스트 완료와 실제 장비 완료는 서로 대체하지 않는다.

- A의 밥을 다른 밥솥으로 옮기는 사용 방식은 이 밥솥의 개방으로 전체 식사 행동을 관측하기 어렵다. 현재 개발 기록만으로 대상 사용자 개인화를 검증했다고 하지 않는다.
