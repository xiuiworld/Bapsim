# B live 자료·실측 평가·발표 결정안 — 2026-10-08

상태: B·팀 승인 전 **검토안**. 이 문서는 수집·평가 조건을 구체화한다. live 전환, 운영 임계값 변경, 실측 성능 승인, 공개 라이선스 합의는 아직 아니다. 수치와 설치 증거는 [운영 검증 결과](B_운영검증_결과_2026-10-08.md)를 따른다.

## 대상과 생산자 조건

대상은 혼자 생활하며 본인이 **관측 대상 밥솥에서 직접 밥을 꺼내 먹는 고령 사용자**다. 공동 사용, 주로 소분·냉동 밥을 먹는 경우, 다른 밥솥으로 옮겨 사용하는 기간은 개인별 식사 패턴 성능 집계에서 제외한다. 개방은 밥솥 사용 행동이며 식사·건강·안전의 확정 증거가 아니다. 현재 A의 옮겨 사용 기록과 보드 `input_kind=test` 보고는 하드웨어·전달 경로 확인 자료다. 개인 학습에 소급 사용하지 않는다.

live 자료는 아래를 모두 확인한 **새 수집 시작 시각 이후**에만 허용한다.

1. 대상 가구·밥솥·사용 방식, 수집 동의 범위, KST 시작/종료 시각과 가명 ID를 등록한다.
2. Matter entry/node, A05 platform/unique_id/attribute path, schema, 보드/SDK/보정/HA/B 버전, 설치 파일·ZIP 해시를 기록한다. 물리 개폐와 극성·단위·시계·순번을 대조한다. `input_kind=live` 선언만으로 적격이 되지 않는다.
3. B의 [A05 검증기](../../service/a05_snapshot_input.py)가 명시적 live·출처·raw snapshot·BootId·ObservationSequence·ReportCounter·신선도 검사를 통과한다. 생산자·매핑·버전이 바뀌면 새 구간으로 분리해 재검증한다.
4. 실제 사용자 행동의 독립 확인 기록을 연결한다. 첫 보고/재부팅/복구 snapshot은 개방이 아니며 순번 공백·offline은 관측 불가로 닫는다. 과거 test의 필드 변경이나 일괄 live 재표시는 금지한다.

## 대상 기간·독립 라벨·학습 제외

| 구간 | 요구 |
|---|---|
| 등록·검증 | 물리 개폐→보드→HA→B를 확인한 시각과 버전을 기록. 해당 시험 구간은 학습·평가에서 제외 |
| 초기 이력 | 평가 시작 전 가구별 최소 **21일** 적격 이력. 정책의 정상 관측 7일·유효 사용 5일도 확인하되, 7/5는 화면의 개인화 후보 조건이지 성능 표본 수가 아님 |
| 실측 보류 평가 | 이후 사전에 고정한 정책으로 **연속 28일** 수집. 다른 가구와 이후 기간을 별도 보류 자료로 남기고 같은 자료로 임계값 선정과 합격 판정을 겸하지 않음 |
| 부족 자료 | 기간·독립 라벨·관측이 모자라면 탐색 사례로만 보고하고 실측 합격/정확도 수치를 내지 않음 |

관측과 라벨은 가명 `household_id`·`device_id`로 분리한다. 센서 원시, 보드 추정, Matter/HA 수신, B 수용·판단·첫 요청, HA 수락, 폰 도착·응답을 각각 다른 시각과 단계로 남긴다. 사용자 또는 보호자는 **알림이 없는 날짜까지 매일 같은 질문**으로 `check_needed`/`no_check_needed`/`unknown`을 확인한다. 판정 주체·시각·절차는 접근 제한 기록에 두고 민감한 자유 서술은 평가 JSONL에 넣지 않는다. 검토자는 가능하면 모델 후보를 보지 않는다. 진짜 요청 지연을 평가하려면 독립적으로 확인한 사건 **시작 시각**이 필요하다. 날짜만 있으면 자정 기준 대리값으로만 표시한다.

설치·시계 교정, 의도적 시험, `test`, 외출·여행, 다른 밥솥 사용, 공동 사용, HA/Core/Matter/Windows 연결 대기, 순번 공백, 미검증 heartbeat, 라벨 `unknown`은 학습과 성능 분모에서 제외하고 사유·시작/끝·가구일 수를 보고한다. 보류에 따른 **발송 억제**와 **학습 제외**도 따로 기록한다. 현재 UART의 큰 결측과 짧은 표본 공백, 보관한 HA snapshot/history에 없는 보고는 관측 불가 또는 미대조로 남긴다. `reconnects=0`이나 프로세스 생존으로 공백을 채우지 않고 미사용으로 학습하지 않는다.

## 실측 성능 합격 기준안

실측 시작 전에 대상군·정책 버전·평가 시작일·라벨 절차와 아래 수치를 B·팀이 승인해 고정한다. 다음은 **승인 전 제안값**이다. 연속된 확인 필요 날짜를 한 사건으로 묶고 동일한 적격 구간·발송 정책을 개인화와 고정 기준선 양쪽에 적용한다.

| 지표 | 제안 문턱 | 필수 보고 |
|---|---|---|
| 불필요한 첫 요청 | 독립 `no_check_needed` 유효 **28가구일당 1건 이하** | 건수/분모, 가구별 결과, 후보·요청·HA 수락·폰 도착 단계 |
| 사건 포착 | 독립 `check_needed` 사건의 **90% 이상**에 첫 유효 요청 | 포착/전체 사건 수, 미포착 사유, 신뢰구간, 가구별 결과 |
| 첫 요청 지연 | 독립 사건 시작→첫 유효 요청 **p95 2시간 이하** | 중앙값·p95·최대값, 야간/보류/전송 단계. 시작 시각 없으면 판정 보류 |
| 자료 경계 | test→live 재분류 0건, 결측을 미사용 학습한 사례 0건, 복구 snapshot 신규 개방·과거 알림 일괄 발송 0건 | 제외 구간, 누락/중복, 버전·설정·해시 |

모집 목표는 **5가구 이상, 독립 양성 사건 30건 이상, 독립 음성 28가구일 5묶음 이상**이다. 미달이면 비율이 좋아도 판정 보류한다. 이 규모도 임상적 안전성이나 일반화를 보장하지 않으므로 신뢰구간과 가구별 차이를 함께 검토한다. 10월 15일 발표까지 조건을 채우지 못하면 합성 기능 결과만 제시한다. 현재 밥솥 단독/보조 합성 사건 **각 3/4 포착**, 날짜별 `3/0/3/18`은 실측 문턱의 통과·실패 판정에 사용하지 않는다.

## 발표 주장과 공개

현재 근거로 설명할 수 있는 범위: 개발용 test 센서→HA→B 시험 알림, HA 내부 모드 소프트웨어와 합성 시나리오, 10월 8일 실제 설치·백업·격리 복원·보류 자동 만료, 외부망 시험 알림·대시보드 조작, 장시간 자료에서 **발견한 결측**. 격리 합성 상태의 활성 사건·발송 복원 및 확인 중/완료는 실제 폰 실기로 소개하지 않는다.

현재 근거로 주장할 수 없는 범위: 대상 사용자의 식사·건강 상태, 실사용 개인화 정확도, 운영 live 사건의 폰 도착·응답, 24시간 무누락, HA OS/Matter Fabric 전체 복구, 보조 활동의 실측 성능 개선. 설치 ZIP `8fb94dca61206e9a368c6cde4c2cc3f93377863b243992037a58e5e44752fa4f`와 최신 main 커밋은 별도 버전으로 적고 발표 전 설치본 범위를 재확인한다.

자체 라이선스는 팀 합의가 없으므로 **미결정**이다. `LICENSE`를 임의 추가하거나 검토용 B 소스 ZIP을 공개 게시하지 않는다. 팀이 라이선스 종류·저작권자, `paho-mqtt==2.1.0`의 EPL 2.0/EDL 1.0 고지, 공개 파일 목록, 개인 기록·토큰 제외를 승인한 후 공개 여부를 정한다. 발표에서 공개 소스 사용 허가를 암시하지 않는다.

## 남은 자료와 승인

- 대상: 위 사용 방식에 맞는 가구·밥솥을 가명 등록. 현재 A의 test/옮겨 사용 기록과 분리.
- 기간: 생산자 검증 이후 21일 이력 + 28일 보류 평가. 10월 14일 종료 예정인 개발 기록을 소급 편입하지 않음.
- 라벨: 알림 없는 날까지 독립 확인한 날짜별 필요 여부, 지연 평가용 사건 시작 시각, 미확인 `unknown`.
- 승인: B·팀이 생산자 체크리스트, 표본·성능 문턱, 발표 문구, 라이선스·고지를 날짜와 버전으로 기록. 승인 전 live 전환·실측 합격·소스 공개는 미완료.

원본 `local-data/`와 HA 백업은 Git에 올리지 않는다.
