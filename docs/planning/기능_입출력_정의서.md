## 1. 대상과 서비스 목적

**혼자 사는 부모님을 걱정하는 자녀에게, 평소와 다른 밥솥 사용 흐름을 알려 자연스럽게 안부를 확인하도록 돕는다.**

- 대상은 독거노인과 자녀다. 자녀가 설치·초기 설정하고, 이후에는 관측을 바탕으로 자동 판단한다.
- 부모님마다 다른 생활 패턴을 배우는 것을 우선한다.
- 이번 대상은 밥솥에서 밥을 꺼내 먹는 생활을 하는 사람이다. 매번 취사하는 생활과 보온하면서 여러 끼 먹는 생활을 포함하고, 소분·냉동 보관을 주로 하는 사람은 제외한다.
- 실제 식사 횟수·섭취량·남은 밥의 양을 계산하거나 모든 예외 생활 방식을 분류하는 기능은 이번 범위에서 제외한다.
- 서비스의 관심은 여러 끼 동안 식사 관련 행동이 없을 가능성이다. 실제 섭취나 끼니 수를 센서로 확인했다고 표현하지 않는다.
- 알림은 따뜻한 말투로 안부 확인을 권하되, 어떤 관측에 근거했는지 설명한다.

## 2. 확정 요구·우선 방향·대안

| 항목 | 인터뷰에서 선택한 방향 | 어려울 때 허용한 대안 |
|---|---|---|
| 밥솥 상태 파악 | 관측으로 구분 가능한 상태를 가능한 풍부하게 파악 | 취사·보온·비활성·판단 불가를 기본 후보로, 가능한 예약 관련 추정 검토. 구분 불가능한 상태를 억지로 확정하지 않음 |
| 개인별 생활 해석 | 밥솥에서 밥을 꺼내 먹는 사람의 사용 간격·시간대·요일별 차이를 학습 | 소분·냉동 생활 방식 해석은 이번 범위 밖 |
| 짧은 반복 개방 묶기 | 우선 규칙 기반으로 하나의 사용 행동으로 묶기 | 첫 개방부터 60분 고정 창으로 합의. 뒤의 개방으로 연장하지 않음 |
| 보온이 꺼진 상태의 개방 | 별도 사용 행동으로 기록하고 개인 패턴으로 해석 | 최근 취사·온도 등 이력으로 식사 가능 행동에 포함할지 판단 |
| 미사용 판단 | 개인의 평소 사용 간격·예상 시간과 비교 | 규칙형은 두 예상 사용 창 연속 미관측으로 안내 후보. 불규칙형은 개인 간격 비교. 실제 두 끼 결식으로 해석하지 않음 |
| 초기 개인화 | 일반 초기 기준과 선택적 생활 습관 입력으로 시작, 약 일주일을 초기 학습 구간으로 두고 계속 개인화 | 일주일 뒤 학습 완료로 단정하지 않음. 초기 입력·기록이 모두 부족하면 패턴 푸시 보류. 충분성은 정책 문서 기준 |
| 장기 변화 | 최근 기준을 갱신하되 장기 기준과도 비교 | 점진적인 감소를 새 정상으로 흡수하지 않도록 비교 유지 |
| 외출·외식 맥락 | 다른 기기 정보를 자동 참고 | 보조 기기가 없으면 밥솥 기반 분석 유지 |

위 표는 최신 합의에 맞춘 구현 방향이다. 초기 인터뷰의 ‘반복 개방도 개인화 우선’과 ‘다음 식사 시간까지 기다리는 첫 알림 대안’은 후속 정책에서 구체화했다.

### 개인화와 알림 정책의 분리

같은 분석 코드가 개인별 기록과 학습된 기준을 관리한다. 사용 시간·간격과 요일별 차이를 배우되 모든 사람에게 아침·점심·저녁 사용을 기대하지 않는다. 반복 개방 정리와 알림 중복·방해금지 처리는 규칙으로 구현할 수 있다.

학습 모델은 평소 패턴과의 이탈을 판단하고, 별도 알림 정책이 발송 시점과 재안내를 정한다. 매 행동을 분석한다고 매 끼니 알리지 않는다. 대화에 나온 ‘누구나 24시간 미사용이면 안내’는 비교용 고정 규칙 예시이며 채택한 방식이 아니다. 현재는 두 예상 사용 창의 연속 미관측으로 합의했으며, 실제 두 끼 결식이라는 뜻은 아니다.

초기 약 일주일의 관측 이후에도 개인 기준을 보정한다. 로컬 학습·추론은 별도 밥심 코드가 담당하며 HA가 자동으로 개인 패턴을 학습해 주는 것은 아니다. LLM 사용을 전제로 하지 않는다.

## 3. 입력 정보의 의미

### 3.1 밥솥 관측

| 입력 | 무엇을 관측하는가 | 해석의 경계 |
|---|---|---|
| 자석 개폐센서 | 실제 뚜껑 열림·닫힘 관련 접점 변화 | 개방은 식사 가능 행동의 단서이며 섭취 확인이 아님 |
| 열림/잠김 LED용 광센서 | 해당 표시등의 점등·점멸 | 실제 뚜껑 개방과 구분 |
| 보온 LED용 광센서 | 보온 표시등의 점등·점멸 | 표시와 운전 상태의 관계를 확인할 필요가 있음 |
| 백미 LED용 광센서 | 백미 표시등의 점등·점멸 | 메뉴 선택과 실제 취사를 동일하게 보지 않음 |
| 상단 맨 왼쪽 LED용 광센서 | ‘예약 2시간 / 찜 10분’ 공유 표시등의 점등·점멸 | 단일 LED로 예약 여부·전체 남은 시간을 확정하지 않음. 소등도 예약 없음으로 단정하지 않음 |
| NTC 온도센서 | 설치 지점의 온도 변화 | 밥의 양이나 내부 음식 상태를 직접 측정하는 정보가 아님 |

광센서는 구매한 5개 중 4개 사용·1개 예비 계획이다. 사용자 첨부 설명서 17쪽 화면의 예약 시간은 **예약 취사 완료까지 남은 시간**이며, 취소까지 남은 시간이 아니다. 실제 기기에서의 점등 동작은 아직 검증 전이다.

### 3.2 선택적 보조 기기 정보

사용자가 정한 우선순위는 다음과 같다. 이번에는 실제 보조 기기 추가 없이 가상 입력으로만 결합 로직을 검증한다.

1. 현관문 개폐: 외출·외식 가능성의 참고 근거.
2. 집 안 움직임: 다른 생활 활동이 관측됐는지 참고.
3. 다른 가전·조명 사용: 추가 생활 활동 근거.
4. 그 외 연결된 기기 중 해석 가능한 정보 활용.

현관 개폐만으로 사람의 이동 방향·귀가·실제 외식을 확인하지 않는다. 다른 관측과 개인 패턴을 함께 참고한다. 기기 미설치·단절·오래된 데이터는 활동 없음으로 계산하지 않는다. 보조 정보로 무한 보류하지 않는다. 정책 문서의 30분 보류·총2시간 한도를 평가용 후보로 두고 가상 입력으로 검증한다.

### 3.3 설치 시 선택적 입력과 알림 설정

| 입력 | 용도 |
|---|---|
| 평소 집에서 밥솥의 밥을 꺼내 먹는 시간대 | 집 밖에서 먹는 끼니를 밥솥 미사용으로 잘못 세지 않도록 초기 예상 시간 구성 |
| 한 번 취사한 밥을 대략 몇 끼에 나누어 먹는지 | 취사 이후 사용 흐름을 해석하는 초기 참고값 |
| 평소 보온 사용 여부 | 개방과 보온의 관계를 이해하는 초기 참고값 |
| 요일별로 다른 생활 습관 | 평일 점심 외식 등 반복적인 차이를 초기 기준에 참고 |
| 자녀의 알림 방해금지 시간 | 해당 시간의 발송을 보류하고 아침에 최신 상태로 재평가 |

생활 습관은 모르면 건너뛸 수 있으며 기록으로 보정한다. 실제 취사량을 센서로 알 수 없으므로 ‘대략 세 끼’ 입력을 정확한 남은 끼니 수로 변환하지 않는다. 자녀에게 매번 외출 여부를 입력하도록 요구하지 않는다.

## 5. 사용 행동과 개인별 패턴 해석

- 보온 중 개방은 식사 가능 행동의 주요 단서다. 가까운 시간의 여러 개방은 하나의 행동 묶음으로 다룬다.
- 취사 직후 첫 개방도 식사 가능 행동에 포함한다. 밥 섞기·확인 등 다른 행동일 수 있으므로 실제 한 끼로 확정하지 않는다.
- 보온이 꺼졌다는 이유만으로 행동을 버리지 않는다. 모든 개방을 기록하고 개인 패턴에 따라 해석하는 것이 우선이다.
- 취사 후 개방·보온 종료도 관측 이력으로 남긴다. 소분 여부를 식별하거나 냉동 보관 후 식사까지 추적하는 별도 기능은 만들지 않는다.
- 취사 후 예상 개방 횟수를 초기 설정으로 참고할 수 있지만, 정확한 취사량·섭취량·남은 밥의 양은 알 수 없다.
- 핵심 감지 대상은 **예상 사용 시점의 지연 또는 긴 공백**, **며칠간 사용 횟수의 점진적 감소**다. 시간대 이동만의 이상 감지나 취사 완료 후 지연만의 별도 알림은 핵심 요구로 추가 확정하지 않았다.
- 최근 패턴을 반영하면서도 이전 장기 기준과 비교한다. 지속적인 감소를 학습 과정에서 그대로 정상화하지 않도록 한다.
- 사용이 재개되면 현재 사용 공백은 해소하되, 장기적인 감소 추세 판단은 유지한다.

## 6. 예약 취사와 알림 시간

야간 취사 완료 후 바로 개방하지 않는 것은 자연스러울 수 있다. 취사 완료만으로 즉시 다음 개방을 기대하지 않고, 개인의 평소 집에서 밥을 꺼내 먹는 시간과 비교한다. 야간 식사 습관이 있는 사람도 개인 패턴으로 다룬다.

추가 시간 LED는 예약 관련 해석을 돕는 입력이다. 그 입력을 확보했다는 이유만으로 예약 모드나 취사 완료 예정 시각을 확정하지 않는다. 정확한 예약 정보가 없는 경우에도 개인 식사 시간으로 판단할 수 있도록 한다.

방해금지 시간에는 안내를 보류한다. 아침 발송 전에 최신 관측과 판단 상태를 다시 확인하고, 이미 해소된 미사용 안내는 보내지 않는다. 실제 미사용 안내가 발송되지 않았다면 그 공백에 대한 사용 재개 알림도 보내지 않는다.

연결 문제·사용 재개 등 알림 유형별 방해금지 적용 범위, 아침 시각, 여러 사유가 겹친 경우의 통합 문구는 상세 설계에서 정한다. 이 문서에서는 조용한 시간에 오래된 미사용 안내를 즉시 발송하지 않는 원칙을 확정한다.

## 7. 보호자에게 보이는 결과

### 7.1 화면

**자녀 휴대폰의 기존 Home Assistant Companion 앱에서 밥심용 화면을 보고 실제 푸시 알림을 받는다.** HA 서버는 노트북에서 실행되고, HA 대시보드는 휴대폰 앱에서 표시한다. 별도 모바일 앱 개발은 기본 범위에 넣지 않는다. 노트북 화면만 표시하는 것으로 서비스나 시연을 완료하지 않는다.

휴대폰 알림 수신과 알림을 눌러 상세 화면에 접속하는 경로를 각각 준비한다. 부모님 집 밖의 네트워크에서도 상세 화면을 열 수 있도록 원격 접속을 구성하며, 접속 방식은 HA Cloud 무료 체험으로 합의했다. 확인·기간 보류 조작도 외부망에서 확인한다.

첫 화면은 최근 사용 시각, 평소 대비 변화, 안부 확인 안내와 관측 상태를 간단하게 보여준다. 누르면 취사·보온·개방 관련 이력과 알림 이유를 자세히 볼 수 있게 한다. 추정과 관측을 구분해서 표현한다.

기기 연결 끊김·일부 센서 오류·개인 패턴 학습 중은 가능한 범위에서 구분한다. 학습 중은 장치 고장과 같은 뜻이 아니며, 일부 센서 오류와 다른 정상 관측도 함께 표현할 수 있어야 한다.

### 7.2 알림과 이후 처리

| 상황 | 요구 동작 |
|---|---|
| 평소 대비 사용 공백 | 개인 기준으로 이탈 판단 후 별도 알림 정책 적용. 규칙형은 두 예상 사용 창 연속 미관측 후 후보 |
| 다른 활동이 관측됨 | 안내를 조금 늦추되 밥솥 미사용이 계속되면 안내 |
| 안내 후에도 사용 없음 | 다음 예상 식사 시간까지 기다렸다가 재안내 |
| 안내 후 사용 재개 | 사용 기록이 다시 확인됐다는 알림. 현재 공백 해소 |
| 정상적인 매번의 사용 | 사용 재개 알림을 매번 보내지 않음 |
| 발송 보류 중 사용 재개 | 오래된 공백 안내를 취소. 미발송 건의 재개 알림도 보내지 않음 |
| 연결 끊김·관측 불가 | 생활 변화와 구분한 장치/관측 문제 안내 |
| 한 번 사용했지만 장기 감소가 지속 | 현재 공백 해소와 장기 추세 판단을 분리 |

자녀의 ‘확인했어요’와 기간 지정 ‘알림 쉬기’를 포함한다. 확인한 안내의 재안내 보류와 여행 기간의 생활 알림 보류를 구분하고 종료 시 재평가한다. 실제 통화·안전이 확인됐다고 해석하지 않는다. 여행 표지는 정상 패턴 학습에서 구분하되 관측 기록을 삭제하지 않는다.

### 7.3 문구 방향

사용자가 선호한 말투의 예시이며 최종 문구 템플릿은 아니다.

> 오늘은 평소 식사 시간에 밥솥을 여신 기록이 아직 없어요. 부모님께 식사는 하셨는지 안부 전화 한 통 드려보면 어떨까요?

> 밥솥을 다시 사용하신 기록이 확인됐어요.

관측 문제의 예시:

> 현재 밥솥 사용 기록을 확인할 수 없어요. 연결 상태를 확인해 주세요.

‘식사를 거르셨다’, ‘안전이 확인됐다’, ‘외식 중이다’로 단정하지 않는다. 따뜻한 말투와 함께 관측 근거를 설명한다.

## 8. 요구사항 확인용 상황 예시

이 표는 이후 설계·구현이 인터뷰 의도에 맞는지 확인하는 기준이다. 시간값이나 합격 수치를 정한 시험 규격은 아니다.

| 상황 | 기대하는 해석·처리 |
|---|---|
| 한 번 먹는 동안 여러 번 여닫음 | 여러 끼로 중복 집계하지 않도록 행동을 묶음 |
| 취사 직후 첫 개방 | 식사 가능 행동으로 포함, 실제 식사 확정은 하지 않음 |
| 개방 후 보온 종료 | 관측 기록 유지. 소분·냉동 생활 해석 기능은 제외 |
| 밤에 예약 취사 후 아침까지 개방 없음 | 취사 완료 직후 미사용 안내를 만들지 않고 평소 식사 시간 고려 |
| 평일 점심은 정기적으로 밖에서 식사 | 초기 요일 습관과 관측 기록을 기준으로 집에서의 사용 기대 조정 |
| 현관 개폐 후 식사 시간에 밥솥 사용 없음 | 외출 가능성 참고, 개폐만으로 외식·미귀가 확정하지 않음 |
| 보조 기기 연결 끊김 | 활동 없음으로 해석하지 않고 해당 근거 제외 |
| 밤에 보류된 공백이 아침 전에 해소 | 미사용·재개 알림 모두 불필요하게 보내지 않음 |
| 안부 안내 후 사용이 다시 관측됨 | 재개 안내, 공백 해소. 기존 장기 감소 추세는 별도 유지 |
| 최근 사용이 점점 줄어듦 | 단기 기준 적응과 별개로 장기 기준 대비 감소 감지 |
| 밥솥 관측 자체가 끊김 | 생활 활동 감소로 단정하지 않고 관측 문제로 안내 |
| 자녀가 부모님 집 밖에 있음 | 실제 휴대폰 알림 수신과 상세 화면 접속 확인. 노트북 표시만으로 완료하지 않음 |

## 9. 아직 지정하지 않은 항목

- Edge AI의 최종 분류 상태, 모델·학습 방식·보드 실행 세부사항.
- 행동 묶음은 첫 개방부터 [시작, 시작+60분)으로 합의. 오류/단절 경계의 실제 처리 검증은 필요하다.
- 초기 약 일주일 이후의 갱신 방법·데이터 충분성 판단, 최근/장기 비교 기간, 초기 기본값과 입력이 없는 경우의 처리.
- 예상 시간·간격 산정, 감소 추세 판단 기준과 보조 정보의 영향·지연 한도.
- 데이터 누락 중의 판단 보류와 복구 후 이력 처리 세부 정책.
- 첫 공백 안내 원칙은 합의했다. 알림 중복·복합 사유·장기 감소 해소는 정책 후보를 구현하고 평가한다.
- 확인·기간 보류 기능과 HA Cloud 체험 사용은 합의. 실제 화면 구성·응답 연동·최종 문구는 구현 대상이다.
- 보조 기기는 가상 입력만 사용. 실제 추가 기기 구매·연동은 이번 범위 밖이다.
- 핀·배선·최종 클러스터·전송 주기. 필드명·단위·내부 형식은 아래 후속 설계서에서 제안하며 실제 매핑은 검증 전이다.

남은 항목은 실제 지원 검증·구현 상세·정책 튜닝이다. 합의한 원칙과 상세 문서의 평가용 후보 수치를 구분한다.

## 10. 후속 합의 반영 이력

2026-10-02 팀 대화와 사용자 확인으로 소분·냉동 주 사용자 제외, 반복 개방 규칙 처리, 일반 초기 기준에서 약 일주일 학습 후 지속 개인화, 기존 Companion 앱의 실제 폰 알림·화면 활용을 반영했다. 초기 인터뷰 발언은 [인터뷰 기록 · 공개 요약](../IMPLEMENTATION_STATUS.md)에 그대로 보존하고 후속 합의를 덧붙였다.

## 11. 후속 상세 설계 설계서

2026-10-02 사용자 요청으로 [보드 출력·상태 추정 설계서](보드_출력과_상태_추정.md)과 [A–B 데이터 계약 설계서](../contracts/AB_데이터_계약.md)을 작성했다. 관측 항목·분류 후보·필드·단위·시각·품질 처리를 제안하며 이 문서의 서비스 요구를 바꾸지 않는다. 최종 분류 성능, 실제 Matter/HA 매핑, 수치 임계값은 확인 대상이다.

## 팀 검토용 상세 설계 추가

[전체 합의안](팀_상세설계_합의안.md)에 Matter·HA 연결, 분석·알림 정책, 출력 계약, 설치·복구·통합시험 추천안을 추가했다. 기존 아키텍처와 역할을 유지하며, 최종 팀 동의로 갱신한 결정은 해당 합의표를 따른다. 기술 검증·조정 가능한 후보 수치는 별도로 표시한다.
