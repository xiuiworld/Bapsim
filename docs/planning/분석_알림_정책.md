# 분석·알림 정책 설계서

2026-10-02 · 최종 팀 합의 반영본

**행동 원칙과 구현 범위는 합의했다.** 60분 묶음과 두 예상 창 기준을 반영했으며, 감소율·기간 등 명시적으로 후보인 튜닝 수치는 평가 후 조정한다. 기존 사용자 인터뷰의 의도는 [기능 정의서](기능_입출력_정의서.md), 합의한 항목은 [합의안](팀_상세설계_합의안.md)을 따른다.

## 1. 분석과 발송의 분리

관측은 계속 기록하되, 행동 묶음 → 개인 기준과 비교 → 다른 활동 참고 → 발송 정책 순서로 처리한다. 개인화는 집에서 밥솥을 사용하는 시간·간격·요일별 차이를 배우는 기능이다. 알림 간격 자체가 AI 여부를 결정하지 않는다.

대상은 밥솥에서 밥을 꺼내 먹는 독거노인이다. 소분·냉동 주 사용자는 이번 범위 밖이며 실제 섭취·안전·정확한 끼니 수를 추정하지 않는다. 규칙으로 처리하는 단계와 학습하는 단계를 시연 설명에서도 구분한다.

## 2. 행동 묶기 추천

- 실제 닫힘→열림만 개방 사건으로 만든다. 최초/복구 snapshot은 새 사건이 아니다.
- 첫 개방 시각 t부터 [t, t+60분)에 발생한 개방을 같은 사용 묶음으로 기록한다. 추가 개방으로 종료 시각을 연장하지 않는다. 정확히 t+60분의 개방은 새 묶음이다. 중간 오류·단절은 연속성을 끊는다.
- 12:00·12:40·12:55는 한 묶음, 13:00 이후 첫 개방부터 다음 묶음이다. 60분은 식사 최소 시간이나 정확한 식사 횟수 기준이 아니다. 원 개방 기록도 모두 보존한다.
- 보온 중이거나 최근 취사 이력이 있으면 식사 관련 맥락을 붙인다. 보온 꺼짐·추정 불가여도 개방 자체를 삭제하지 않는다.
- 묶음 하나를 ‘한 끼’로 부르지 않는다. `usage_episode`라는 사용 행동 기록이다.
- 상태 추정만 변했거나 예약 LED만 켜진 경우에는 개방 사건을 만들지 않는다.

## 3. 초기 학습과 개인화 추천

첫 모델은 로컬에서 갱신하는 개인별 시간대·간격의 통계 모델을 추천한다. 처음부터 여러 신경망을 추가하지 않는다. 구체 모델 성능은 B가 규칙 기준선과 비교한다. 보드의 운전 상태 Edge AI와는 다른 역할이다.

| 단계 | 추천 동작 |
|---|---|
| 기록 7일 미만 | 선택적 생활 습관을 초기 기준으로 사용. 화면에 학습 중 표시 |
| 입력도 기록도 부족 | 임의의 3끼 시간표를 생성하지 않음. 패턴 기반 미사용 푸시는 보류하고 설정/기록 부족을 표시 |
| 7일 이상 + 유효한 사용일 5일 이상 | 개인화 후보 적용. 모든 요일을 충분히 배웠다고 표현하지 않음 |
| 특정 요일 표본 부족 | 우선 평일/주말 묶음, 그것도 부족하면 전체 개인 기준으로 후퇴. 초기 요일별 외식 입력 존중 |
| 이후 | 하루 한 번 갱신. 최근 14일 사용 시각·간격의 분포를 참고 |

시간대 모델은 자정 경계를 고려하고, 가까운 시각의 사용을 묶어 반복되는 사용 창을 찾는 방향이다. 중앙값 시각과 분산/분위수로 기대 창을 만들며, 한 번의 우연한 사용으로 새 일상 시간대를 만들지 않는다. 반복 시간대가 뚜렷하지 않으면 개인별 사용 간격 모델을 우선한다. 정확한 클러스터링·분위수 구현은 B가 버전과 함께 기록한다.

개인화 사용 가능 여부는 경과 일수뿐 아니라 정상 관측 범위를 본다. 첫 제안은 정상 수집이 하루의 90% 이상인 날을 유효일로 삼되, 이 비율은 수집 상태/heartbeat가 확인된 구간으로 계산한다. 단순히 ‘하루에 이벤트가 몇 개 있었다’로 계산하지 않는다. 관측 범위 산정이 안 되면 충분성도 미확인으로 둔다.

## 4. 첫 안내 민감도 추천

생활 변화 안내는 **연속 사용 공백**과 **며칠간 사용 감소** 두 종류로 합의했다. 단순 시각 이동은 독립 푸시 사유로 만들지 않는다. 첫 공백 안내는 비교적 보수적으로 시작한다. 다음 두 경로는 생활 패턴에 따라 선택하고 같은 공백을 중복 발송하지 않는다.

| 패턴 | 추천 첫 안내 조건 |
|---|---|
| 반복 사용 시간대가 있음 | 예상 사용 창 하나가 지나면 내부 관심 상태. 다음 예상 사용 창도 끝날 때까지 사용이 없으면 안내 후보 |
| 시간대가 불규칙함 | 개인의 유효한 과거 사용 간격 95백분위 초과 시 관심 상태, 그 기준에 2시간 유예를 더 넘으면 안내 후보 |
| 초기 설정만 있음 | 입력한 집에서의 사용 창에 위 첫 경로 적용하되 초기 기준임을 문구/화면에 표시 |
| 기준 부족·공백 중 관측 단절 | 미사용을 확정하지 않고 관측/학습 부족으로 분리 |

‘두 예상 사용 창’은 하루 세 끼를 고정하거나 두 끼를 굶었다고 단정하는 것이 아니다. 하루 한 번 사용하는 사람에게는 더 긴 간격이 된다. D06에서 이 시작 기준을 채택했다. 개인별 예상 창은 평소 변동 폭을 포함하고, 반복 외식 시간은 집에서의 사용 기회로 세지 않는다. 사용이 다시 확인되면 현재 연속 공백은 해소한다. 7시에 사용한 뒤 점심 사용이 늦어져 15시에 사용했다면 18시 정각이라는 이유만으로 안내하지 않는다.

관측 공백이 낀 예상 창은 정상 미사용 창으로 세지 않는다. 복구 후 새 정상 구간에서 평가를 재개하며 화면에는 판단 제한을 남긴다.

## 5. 점진적 감소 추천

최근 7일의 유효일당 사용 묶음 수와 그 이전 최대 21일의 기준을 비교한다. 가능한 경우 요일 구성을 맞춘다. 최소 비교 자료는 최근 유효일 5일과 이전 유효일 10일을 제안한다. 부족하면 감소 추세 판단을 보류한다.

첫 후보 기준은 30% 이상 감소가 3일 연속 평가에서 유지될 때 안내 후보로 만드는 것이다. 단기 적응 기준과 이전 기준을 별도로 보존해 점진적 감소를 즉시 정상으로 흡수하지 않는다. 표본과 민감도가 적절한지는 평가 자료로 조정한다. 합성 기록은 기능 확인용이고 개인 생활에 대한 정확도 근거가 아니다.

한 번 다시 사용했다고 감소 추세를 닫지 않는다. 최근 감소율이 기준 이내로 돌아온 상태가 3회 일일 평가에서 유지될 때 해소하는 안을 제안한다. 장기 감소 재안내는 7일 간격을 시작값으로 두며, 단기 공백 안내와 같은 날 겹치면 한 메시지로 합친다.

## 6. 다른 기기의 보조 정보

우선순위는 현관 개폐 → 움직임 → 다른 가전/조명 사용이다. 기기는 미선정이며 미설치·단절·오래된 데이터는 근거에서 제외한다. 이번 범위에서는 실제 추가 기기를 사용하지 않고 가상 입력으로만 결합 로직을 검증한다. 실제 밥심 입력과 섞은 시험도 전체 실행을 simulation으로 구분하고 실제 개인 기준·보호자 알림에 섞지 않는다.

첫 정책은 안내 후보 시점 이전 2시간 내 유효한 활동 사건이 있으면 30분 보류하고 재평가하는 것이다. 같은 공백에서 활동 근거에 따른 총 연장은 2시간을 상한으로 제안한다. 반복 활동이 있어도 무한 연장하지 않는다. 방해금지 보류는 별도 정책이다.

현관이 열렸다는 이유만으로 외식 확정이나 귀가 미확인 상태를 만들지 않는다. 조명이 계속 켜져 있는 값도 최근 사용자 행동과 같지 않다. 실제 상태 전환과 해당 기기 의미가 해석되는 경우만 활동 근거로 쓴다.

기록상 안내 요청 성공과 폰 도착/열람 확인은 구분한다. 재안내 상태 머신은 서버에서 확인 가능한 발송 결과로 움직이며 ‘자녀가 읽었다’고 가정하지 않는다. 재시작해도 공백 ID·발송 이력·다음 평가 시점을 보존한다.

## 8. 안내 예시와 화면

- 공백: “평소 밥솥을 사용하시던 시간과 조금 다른 흐름이 보여요. 부모님께 식사는 하셨는지 안부 전화 한 통 드려보면 어떨까요?”
- 감소: “최근에는 평소보다 밥솥을 사용하신 기록이 줄었어요. 요즘 어떻게 지내시는지 안부를 여쭤보면 어떨까요?”
- 재개: “밥솥을 다시 사용하신 기록이 확인됐어요.”
- 관측 불가: “현재 밥솥 사용 기록을 확인하기 어려워요. 연결 상태를 확인해 주세요.”

첫 화면에는 최근 사용·평소 대비 변화·현재 안내·관측/학습 상태를 보여준다. 상세 화면에는 근거 이력과 사용 기준을 보여준다. 연결 정상·센서 오류·학습 중은 동시에 존재할 수 있다. 실제 식사나 안전 확인으로 표현하지 않는다. ‘확인했어요’와 기간 지정 ‘알림 쉬기’를 구현 범위에 포함한다. 동작은 아래 10절을 따른다.

## 9. 평가 방법

B는 같은 기록에 고정 간격 기준선과 개인화 방식을 적용해 알림 수, 기대 시나리오와 다른 안내, 관측 불가를 활동 없음으로 오해한 횟수를 비교한다. 실제 식사 정답이 없으면 식사 감지 정확도를 계산하지 않는다. 데이터 분리는 시간 순서로 하여 미래 기록으로 과거 기준을 학습하지 않는다.

부착/보드 모델 정확도 평가는 A, 개인 패턴과 정책 평가는 B가 맡는다. 두 결과와 합성 시나리오 통과 여부를 섞어 하나의 AI 정확도로 발표하지 않는다.

## 10. 확인·여행 기간 보류

- ‘확인했어요’는 현재 안내를 확인했다는 사용자 조작이다. 같은 사유의 재안내를 언제까지 쉴지 ‘오늘까지’ 또는 지정 날짜·시각을 선택해 저장한다. 기간 없는 무기한 해제나 안전 확인으로 바꾸지 않는다.
- 여행 등 ‘알림 쉬기’는 시작·종료 시각을 지정한다. 그 기간의 생활 공백·감소 알림과 관련 재개 알림을 보류한다. 장치/관측 문제 표시는 유지하며 그 알림은 별도 야간 정책을 따른다.
- 보류 중에도 관측 기록을 유지한다. 사용자가 지정한 여행 구간은 정상 패턴 학습과 감소 비교에서 제외할 수 있도록 별도 표지한다. 자료 부족은 부족으로 표시한다.
- 보류 만료·취소 시 과거 알림을 몰아서 보내지 않는다. 현재 관측을 확인하고 다음 정상 예상 사용 창부터 공백을 센다. 추세는 여행 제외 자료가 충분할 때 재평가한다.
- 보류 설정은 서버에 저장해 재시작 후 유지하며, 폰에는 적용 성공 여부와 종료 시각을 표시한다.

## 11. 단발 변화와 학습

늦게 사용한 원본 기록을 지우지 않는다. 단발 지연이 개인 기준을 즉시 바꾸지 않도록 중앙값·변동 범위·갱신 제한 등 B의 모델에 명시적으로 반영한다. 단발값의 영향이 자동으로 무시된다고 가정하지 않는다. 반대로 모든 변화 기록을 배제해 새로운 생활 패턴을 영원히 배우지 못하게 하지 않는다. 최근 기준과 장기 비교 기준을 분리한다.
