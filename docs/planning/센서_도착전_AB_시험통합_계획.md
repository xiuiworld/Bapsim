# 센서 도착 전 A–B 시험 통합·계약 점검·main 병합 계획

작성: 2026-10-05. **계획·리뷰 요청 문서이며 새 공통 계약을 승인하는 문서가 아니다.**

## 1. 목표와 현재 상태

센서 입력만 합성으로 두고 실제 보드의 전처리·AI 결과를 기존 Matter→HA→B 시험 처리→화면 경로로 전달한다. 실물 정확도·개인 학습 완료·식사 여부를 입증하는 시험이 아니다. 폰 알림은 B가 제공하는 명시적 시험 실행에서 지정한 시험 폰으로만 검증한다.

```text
합성 원시 시계열 [A]
 → 실제 nRF54LM20 보드의 20Hz 전처리·상태 추론 [A]
 → SnapshotPacked v1, input_kind=test [A]
 → 기존 Matter/Thread + bapsim_matter_probe [A]
 → 출처 검증·A–B 시험 기록 [B]
 → 격리된 시험 분석/화면·명시적 시험 알림 [B]
 → A가 실제 HA 화면/폰 수신/클릭을 확인
```

현재 보드에서는 합성 원시값 재생→전처리→모델 추론의 PC 대조가 완료됐다. 14가지·33,959표본·442창 대조 오류 0이다. **HA에는 아직 별도 A05 fixture가 전송되고 있으며 AI 결과를 전송하지 않는다.** 기존 B 시험은 닫힘→열림→시험 폰 알림이며 AI 상태 전체 통합으로 확대해 해석하지 않는다.

센서 없이 남은 일은 이 통합 경로, 장애·복구·중복 시험, 실센서 배선/핀/전압 검토와 라벨링 준비다. 센서가 필요한 일은 실제 ADC 취득·극성·주변광·NTC 보정, 부착 안전성, 실측 평가다.

| TemperatureCentiC | 설치 지점 섭씨×100의 nullable int16 | wire null=-32768; B에서 ÷100. 전처리의 오류 대체 0을 유효 온도로 보내지 않음 |
| LidOpen | true=열림, false=닫힘, 모르면 null | wire null=255; 합성 접점과 실제 버튼을 한 출처로 혼합하지 않음 |
| LED | 0=unknown, 1=off, 2=on, 3=blinking | 각 채널 품질 별도. 시간 LED를 예약 확정 신호로 해석하지 않음 |
| SignalQuality | 각 7신호에 0unknown/1good/2error/3unsupported | good이 아닌 enum은 0/null, 온도·접점은 null. 정상값을 오류 품질에 실어 보내지 않음 |
| SnapshotPacked | magic BS05, schema=1, 단일 octet-string, 최대 110B | 경로 `1/4294048769/4293984260`; 원자적 1회 갱신 |
| 시험 출처 | wire test 플래그=1 → HA `input_kind=test` | live로 위장하거나 B 출처 검사를 우회하지 않음 |
| 연속성 | BootId uint32, ObservationSequence/ReportCounter uint32, UptimeMs uint64 | 생산자가 보내는 연속 snapshot 단위로 순번 정의. 20Hz 표본 번호/빠른 재생 루프 번호를 그대로 전송 카운터로 쓰지 않음 |
| B 식별 | household/device, source_ref, stream/record ID | A가 B의 record_id/정규화를 중복 생성하지 않음 |
| B inference | method/version/score; 직접 관측은 null | 판단 불가 기록에서는 현재 B가 inference=null로 변환하므로 원시/실행 메타데이터에서 모델 버전을 추적해야 함 |

샘플링은 20Hz, 온도 특징은 1Hz, 특징 출력은 60초 준비 뒤 2초마다다. 이것은 Matter 보고 주기와 다르다. 기존 A05 시험 송신은 15초, HA는 5초마다 읽는다. 공통 문서의 60초 heartbeat와 구분된 시험 설정이다. 2초마다 전송 순번을 증가시키면 HA가 중간 보고를 놓쳐 B가 관측 공백으로 판정할 수 있다. **초기 통합은 시험 상태를 최소 15초 이상 유지하고, 송신 시점·순번·B TTL을 함께 고정한다.** 정확한 간격과 단절 기준은 PR의 시험 설정에 기록한다. 누락을 숨기기 위해 카운터나 관측 시각을 꾸미지 않는다.

빠른 보드 재생의 가상 시간과 실제 수신 시간도 구분한다. 전달 형식 확인에는 짧은 재생이 가능하지만, B의 시간대/개인 패턴/알림 정책 시험에는 실제 시간 진행 또는 B가 명시적으로 제공하는 격리된 재생 시계를 사용한다. 가속한 1초를 실제 하루 관측으로 위장하지 않는다.

## 4. 발견 사항과 공통 규칙 검토

| ID | 점검 결과 | 처리/담당 |
|---|---|---|
| R1 | A 모델→wire enum/score/온도 단위, A codec→B 기록 매핑은 오프라인 후보 시험 통과 | A의 실제 보드 publisher를 연결한 뒤 다시 실기 확인 |
| R2 | 현재 `Preprocessor::Result`는 x/valid/LED만 제공. 온도·접점의 독립 품질/원 관측을 publisher가 모두 알 수 없음 | A: 별도 관측 결과에 유효 온도·debounce 접점·채널별 품질을 노출. 전체 valid=false여도 정상 채널은 유지. B 정규화 수정으로 숨기지 않음 |
| R3 | 보드 모델 결과→SnapshotPacked 연결 미구현 | A: 기존 codec/명세에 맞는 publisher 추가, 동일 입력 창의 관측·추정을 함께 전달. 서로 다른 fixture와 AI를 섞지 않음 |
| R4 | B 시험 기록 `mode=test`/test_run_id는 기존 전용 시험 경로에 존재하지만 공통 AB 계약 본문 enum은 live/simulation/replay만 정의 | B: 기존 전용 시험 형식임을 공통 문서에 명시하거나 별도 시험 계약으로 연결하는 PR 제안. 팀 검토 전 일반 계약 소비자에게 그대로 통과시키지 않음 |
| R5 | B 현 시험은 닫힘→열림으로 1회 알림; 취사 상태 기반 시험 분석/화면까지 연결한 증거 없음 | B: 기존 구현을 재사용하는 시험 실행 경로 제공. A는 정책/정규화/개인 모델을 복제하지 않음 |
| R6 | test/live 저장 격리 수준은 기능별로 다름: 전용 실행 journal과 기존 논리 분리를 구분해야 함 | B: 각 입력·학습 상태·저장 파일·MQTT topic·화면·폰 대상 경계를 인계. 물리 저장 분리가 된 것처럼 쓰지 않음 |
| R7 | 생산 보고 주기, 센서 보정, 실물 설명서 적용 관계는 아직 실측 확인 전 | 시험용 가정으로 표시. 센서 도착 후 A08에서 검증 |
| R8 | A 변경은 tools/a07_edge와 A 문서; firmware·B 분석·raw event 계약은 수정하지 않음 | 범위 준수. 이후 공통 계약/동작 변경은 영향과 근거를 PR로 검토 |

**규칙:** 기존 규칙에 맞춰 고칠 수 있으면 고쳐서 PR에 포함한다. 규칙 자체가 바뀌어야 하면 계약/예시/생산자/소비자/테스트 영향을 제시한다. 이 문서의 제안만으로 공통 규칙을 변경하거나 main에 직접 push/merge하지 않는다. 합성 정확도·PC 일치를 실측 성능으로 표시하지 않는다.

## 6. 이번 사전 검증과 한계

- A07 PC 테스트 14개 통과. A05 codec/validation 8개 통과.
- B 원격 `b356897` export의 전체 unittest 181개 통과. 알림 실패 테스트에서 출력되는 ConnectionError 로그는 예상 모의 실패이며 최종 테스트 결과는 OK.
- `python -m tools.a07_edge.check_ab_contract --b-root <B 소스>`: inactive/cooking/warming/unknown 4개 후보 snapshot의 codec, B 변환, 온도 단위, 점수·모델 버전, test의 live 거부, 잘못된 출처 거부, 중복 무시, 독립 센서 오류 처리 통과.
- 이는 **후보 데이터와 B 함수의 오프라인 대조**다. 아직 없는 publisher나 B의 전체 시험 분석 경로가 통합됐다는 증거가 아니다.
- 기존 실기 결과는 [A07 기록](../hardware/A07_합성학습_검증.md), 이전 개폐→폰 결과는 [A06 기록](../hardware/A06_HA_OS_배포_검증.md) 참조.
- 첫 A05 테스트 호출은 오래된 절대 import 때문에 패키지 경로 실행에 실패했다. `unittest discover -s tools/a05_contract`로 올바르게 실행해 8개 통과. 실패를 감추거나 제품 코드 수정으로 우회하지 않았다.

## 7. PR·main 병합 절차

1. 이번 A07 코드·검증 문서·통합 계획은 A 전용 브랜치에 commit/push한다. 대용량 local-data, 비밀번호/.env, 빌드·HA 백업, firmware 파일은 stage하지 않는다.
