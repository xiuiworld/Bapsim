# 실물 Matter 수신 검증 기록

이 기록은 실제 장비 로그로만 완료 칸을 채운다. 시뮬레이터와 가짜 HA 테스트는 현물 성공 증거가 아니다. 절차는 [실물 연결 가이드](실물_밥솥_연결_가이드.md)를 따른다.

심사 항목별 실물 증거와 Multi-Admin 시험 항목은 [하드웨어 심사 대비 실물 검증표](하드웨어_심사_실물_검증표.md)를 따른다.

## 2026-10-02 현재 환경 확인

| 항목 | 확인 결과 |
| --- | --- |
| 로컬 HA | `bapsim-homeassistant` 컨테이너 실행, `http://127.0.0.1:8123/` HTTP 200 |
| HA 설정 | `check_config` 통과, 수정된 밥심 통합을 로드하도록 컨테이너 재시작 |
| Matter 통합 | 현재 HA의 config entry 목록에 `matter` 없음 |
| 하드웨어 담당 진행 상태 | 사용자 확인: 보드·네트워크 구성 준비 중. commissioning 가능 상태 아님 |
| 실물 센서 수신 | 미검증. 장치 commissioning 및 HA entity 기록 없음 |
| 소프트웨어 모의 검증 | Python 자동 테스트 58개 통과. 접점 단독 원시값은 기록하고 분석은 오프라인으로 유지하며, 나중에 취사 입력을 등록해도 과거 접점값을 새 행동으로 세지 않는 경우와 비Matter 출처 거부·출처 변경·복구·엔티티 제거, 미등록 취사 상태의 진단 표시와 판정 보류, 보조 Matter 기기 원시 입력 분리·복원, 보드 관측·추정 분리 및 추정 단절 때 관측 유지, 보드 이력 저장·복원, 검증된 추정값의 취사 매핑, 배포 ZIP의 독립 import 포함 |
| 별도 HA 호스트 배포 | 배포 ZIP만 사용한 독립 Home Assistant 2026.9.0 컨테이너에서 HTTP 200·`check_config` 통과, `PYTHONPATH=None`과 번들 내부 import 확인. 시험 컨테이너 종료. HA OS 설치·실물 Matter 수신은 미실행 |

## 취사 입력이 검증된 뒤

사람이 기록한 메뉴 선택·취사 시작·취소·완료·보온 전환과 센서 및 HA 값을 대조한 뒤에만 `started_state`/`finished_state`를 등록한다. 두 상태를 구별할 수 없으면 `미지원`으로 기록하고 실물 기반 취사·개방 지표를 보류한다.

| 관문 | 완료 증거 | 결과 |
| --- | --- | --- |
| 취사 시작·완료 구별 | 조작 시각, Matter 값, HA entity 값과 로그 | 미실행 |
| 원시→정규화 접점 전이 | `lid_state`와 2초 후 `lid_opened/lid_closed` 로그 | 미실행 |
| 세션·특징·판정 | 실물 취사·개방 로그와 밥심 이벤트 대응 | 미실행 |
| 단절·복구·HA 재시작 | 공백 처리와 중복 행동 없음 | 미실행 |
| 엔티티 교체·출처 변경 | 예전 매핑 차단, `source_unverified` 또는 재등록 후 정상 복구 | 미실행 |
| 로컬 알림·보호자 응답 | 실제 사건 기록과 처리 상태 | 미실행 |
| 휴대폰 외부망 수신·응답 | Wi-Fi를 끈 보호자 폰의 수신·액션 기록 | 미실행 |
| Multi-Admin 두 Controller 동기화 | 두 Controller의 식별 정보, 추가 절차, 동일 조작의 양쪽 상태·시각 | 미실행 |
| 부착·내구·설치 재현 | 부착 사진, 열·증기 및 반복 사용 기록, 원가·설치 시간 | 미실행 |
