# 실사용 데이터 없는 강건성 실험 — 2026-10-03

**대상 범위 주의 (2026-10-04):** 아래 기존 4유형 비교에는 이번 제품 대상에서 제외한 격일·3일 간격 조리 유형과 50~64세 유형이 섞여 있다. 이는 범위 밖 스트레스 시험으로만 읽어야 한다. 운영 모델 선택이나 대상 가구의 포착률 근거로 사용하지 않는다. 소분·냉동 주 사용자를 제외한다는 [기능 정의](planning/기능_입출력_정의서.md)에 맞춘 별도 집계는 아래에 기록했다.

## 차용한 방법

- [Domain randomization (Tobin 등, 2017)](https://arxiv.org/abs/1703.06907)은 시뮬레이션의 조건을 다양하게 바꾸어 한 생성 조건에 맞춰지는 문제를 줄인다. 원 논문은 로봇 영상에 적용했다. 여기서는 **아이디어만 차용**해 자연스러운 미사용률, 사용 시각 흔들림·이동, 개방 신호 누락을 가상 가구마다 바꾼다. 이 적용이 실제 밥솥 사용으로 전이된다는 증거는 아니다.
- [Group DRO (Sagawa 등, 2020)](https://arxiv.org/abs/1911.08731)는 미리 정한 집단 중 가장 나쁜 손실을 줄이는 학습을 연구한다. 여기서는 신경망 학습이 아니라 **후보 설정 선택에만** `생활 리듬 × 교란 유형`별 최대 손실을 사용했다. 손실은 `1 − 중단일 당일 발송 요청 포착률 + 2 × 정상일 발송 요청률`이다. 이 목적함수와 2배 가중치는 밥심 실험 가정이다.
- [시계열 순차 검증 (Hyndman·Athanasopoulos)](https://otexts.com/fpp3/tscv.html)의 미래 정보 누출 방지 원칙에 맞춰 각 가구의 과거 21일을 먼저 입력하고 다음 21일을 날짜 순서대로 평가했다. 가구·난수 시드·조건이 다른 보류 집합을 선택에 쓰지 않았다.

## 실행과 결과

`python -m ai.robust_notification_experiment`로 재현한다. 훈련에는 기존 생활과 별도로 시각/건너뜀 변화, 개방 신호 8% 누락을 넣었다. 보류 집합에는 두 변화를 **동시에** 넣고 다른 가구 시드와 조건을 사용했다. 4개 알림 후보를 비교해 훈련의 최악 집단 손실이 가장 낮은 `single_high_confidence`를 선택했다.

| 설정 | 훈련 최악 집단 손실 ↓ | 훈련 포착 / 정상일 요청 | 보류 복합 조건 포착 / 정상일 요청 |
|---|---:|---:|---:|
| 현재 운영 설정 | 1.1334 | 25.0% / 4.4% | 13/64 (20.3%) / 11/240 (4.6%) |
| 강건 선택 후보 | 1.1041 | 24.0% / 8.1% | 9/64 (14.1%) / 15/240 (6.3%) |

훈련의 최악 집단 숫자는 조금 좋아졌지만 **보류 복합 조건에서는 포착이 낮고 정상일 요청은 많았다.** 따라서 이 후보를 운영 모델에 적용하지 않았다. 기존 모델·알림 기준을 유지한다. 특히 격일 사용 가구는 두 설정 모두 보류 중단일 16건 중 당일 요청 0건이었다. 사건 단위로 보면 현재 설정은 32건 중 13건을 포착했고 포착 건의 중앙 알림 요청 지연은 24.82시간이었다. 두 지표 모두 실제 보호자 도착을 뜻하지 않는다.

훈련·보류 시나리오는 모두 같은 프로그램으로 설계한 **가상 가정**이다. 보류 성능도 현장 성능 추정치가 아니다. 센서 누락 확률 역시 측정값이 아니라 스트레스 값이며, 놓친 개방과 실제 미사용은 센서만으로 구분되지 않을 수 있다. 이 실험의 성과는 새 모델이 더 정확하다는 결론이 아니라, 평균 성능만 보고 운영값을 바꾸면 취약한 생활 유형에서 악화될 수 있음을 재현한 것이다. 실행 결과 전체는 [JSON](../ai/robust_notification_result.json)에 남긴다.

## 이번 대상 가구만 다시 집계

같은 보류 시드·교란 조건에서 65세 이상이며 평소 **매일 사용 기회가 있는** 아침 1회·하루 2회 합성 유형만 포함했다. 자연스러운 미사용일은 여전히 발생한다. 격일 조리 유형과 50~64세 유형은 제외했다. 현재 운영 기준으로 사용 중단 사건 **9/16건**에서 보호자 알림 요청이 있었고 **7/16건**을 놓쳤다. 정상일의 불필요한 요청은 **7/120일**이었다. 아침 1회는 7/8건, 하루 2회는 2/8건을 포착했다. 두 유형만의 작은 합성 집단이므로 제품 대상 전체를 대표하지 않으며 실측 성능도 아니다. 가상 재생은 예상 창 뒤 하루 몇 시점에서만 평가하지만 실제 HA는 60초마다 평가하므로, 여기서 계산한 요청 지연은 운영 지연의 검증값이 아니다. `python -m ai.target_scope_audit`로 재현할 수 있으며 [결과 JSON](../ai/target_scope_audit_result.json)에 분모와 생활형별 값을 남겼다.

추가로 이 생성기는 **이틀 연속의 계획된 사용일 전체**를 중단한다. 하루 1회 유형은 두 개방, 하루 2회 유형은 네 개방을 제거하므로 유형 간 사건 난도가 동일하지 않다. 사건 종료 다음 날 나온 요청 1건은 현재 일자별 표에서 정상일 요청으로 집계된다. 생활형별 포착률이나 정상일 요청을 직접 비교해 모델 우열을 정하면 안 된다.
