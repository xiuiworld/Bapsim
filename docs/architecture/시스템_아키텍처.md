# 시스템 아키텍처

## 데이터 흐름

센서 → 보드 관측/상태 추정 → Matter over Thread → Nest Hub → HA 수신 → 정규화·저장 → 개인 패턴 → 화면·알림·보호자 응답.

보드는 nRF54LM20-DK, 보더 라우터는 Nest Hub 2세대다. 기본 분석 실행 위치는 Home Assistant 내부이며 HA 호스트는 계속 켜져 있어야 한다. 보드의 USB 충전기 구동만으로 전체 시스템이 PC 없이 동작하는 것은 아니다.

## 경계

- 보드: ADC/GPIO 취득, 센서 품질, 개폐·온도·LED 관측, 운전 상태 추정, 버전/순번을 가진 Snapshot.
- Matter/HA 입력: 출처·스키마·품질·부팅·순번 검사, 원시 계약 보존. 판단은 입력 어댑터에 넣지 않는다.
- 분석: 첫 개방부터 고정 60분 사용 묶음, 개인 시간·요일·간격과 장기 변화, 관측 공백 제외.
- 출력: 실물/가상 경로 분리, 상태 만료, 중복 억제, 보호자 확인·기간 보류·취소·복원.

Google Home과 HA는 같은 보드에 각각 등록하는 Multi-Admin 구조다. Google Home에 저장된 데이터를 HA로 복사하지 않는다. 제조사 API와 원격 취사 제어를 사용하지 않는다.

## 정보의 의미

개방은 사용 가능 행동이고 식사 완료가 아니다. 보드 상태 추정과 개인 패턴 판단은 별개이며 각각의 버전·근거·입력 품질을 보존한다. 단절·재부팅·순번 공백을 정상 미사용으로 처리하지 않는다. 합성 및 `test` 입력은 운영 개인 학습과 분리한다.

독립 MQTT 작업자는 선택적 실행 모드다. 이번 설명의 보드 맥락 연결은 HA 내부 분석 모드를 기준으로 한다. 두 모드를 동시에 운영하지 않는다.
