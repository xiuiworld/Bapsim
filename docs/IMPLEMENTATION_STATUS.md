# 밥심 구현 상태 — 2026-10-03

현재 저장소의 담당 범위는 Home Assistant(HA) 수신 이후다. Nordic 펌웨어·보드 Edge AI는 다른 담당자의 범위다. 이전 구현 기록은 [구현 점검](구현_점검_2026-10-02.md)에 남아 있다.

## 현재 소프트웨어

- 원시 8필드 이벤트 → 접점 상태 전이·단절 정규화 → [개인별 사용 패턴 모델](개인화_사용패턴_모델.md) → 알림 상태 관리. 모델은 일반 초기 시간대에서 시작해, 구간별로 연결이 확인된 과거 7일을 학습한 뒤 개인의 예상 시각과 사용 확률을 계속 갱신한다. 이전 하루 횟수 기준선과 `RuleDetector`는 활성 HA 판정에 사용하지 않는다.
- HA는 정규화된 뚜껑 개방만으로 모델을 학습할 수 있다. 취사 신호는 세션·특징 진단용으로 계속 받지만, 등록되지 않거나 끊겨도 접점 모델을 오프라인으로 만들지 않는다. 접점 단절, 외출, 학습 부족은 결측·보류 상태로 구분한다.
- 예상 구간의 개방 누락이 높은 확률로 판단되면 `check_required`를 낸다. 서로 다른 예상 구간에서 36시간 안에 연속 두 번 발생하면 보호자 사건을 만들고 HA 로컬 알림과 등록된 Companion 앱 서비스를 호출한다. 중복 알림 제한, 보호자 확인·완료 응답, 재시작 복원이 있다.
- `bapsim.set_away`로 부재를 선언·복원한다. 외출 중 관측되지 않은 개방은 학습하지 않으며 활성 사건은 해결 상태로 닫는다. 실패한 휴대폰 서비스 호출은 활성 사건에 한해 저장·재시도한다.
- HA Matter 접점·취사 엔티티를 원시 이벤트로 바꾸는 등록 서비스, 보드 관측·추정 신호의 원시 수신, 선택적 타 Matter 기기의 독립 원시 수신이 있다. 출처가 Matter가 아닌 엔티티는 거부한다. 추정 신호를 검증된 행동으로 자동 승격하지 않는다.
- HA 설정 폴더의 `bapsim_events/`에 원시 이벤트를 UTC 날짜별 JSONL로 계속 기록한다. 최근 1,000건 보드 신호는 HA 저장소에서도 빠르게 조회할 수 있다. JSONL의 백업·보존 기간·디스크 용량은 운영 환경에서 관리해야 한다.
- 취사 세션·24시간 특징·이전 일별 기준선/규칙과 Colab 가중치 후보 코드는 비교와 진단을 위해 남아 있다. 이전 가중치 후보는 현재 개인화 모델에 적용되지 않는다.
- 현재 `PersonalUsageModel`의 가상 가구별 시간 순서 학습·보류 가구 평가용 [Colab 노트북](../ai/밥심_개인사용패턴_학습_Colab.ipynb)을 별도로 만들었다. 합성 결과는 운영 확률 기준을 자동 변경하지 않으며 실제 생활 데이터 검증을 대체하지 않는다.
- [개인화 평가 기록 규약](개인화_평가_기록_규약.md)에 관측과 독립 확인 라벨의 JSONL 형식, 외출·단절·heartbeat 공백 제외 기준을 정의했다. 두 가상 가구 기록 생성기와 로컬 시간 순서 재생 평가기를 추가했으며 실측 라벨이나 운영 알림 설정에는 아직 적용하지 않았다.

## 10월 3일 소프트웨어 변경

- 활성 개인화 모델의 반복 개방 처리 기준을 첫 개방부터 60분 고정 창으로 맞췄다. 모델 상태에 원 개방 시각과 묶음 시작을 함께 저장하고 재시작 때 복원한다. 원시 이벤트 경계는 그대로 둔다.
- 최근 7일의 유효일당 사용 묶음과 이전 최대 21일을 비교하는 감소 판단을 추가했다. 최근 5일·이전 10일 이상 확보하고 30% 이상 감소가 3회 일일 평가에서 유지될 때 별도 사건을 만든다. 세부 수치는 평가용 후보이며 실측 성능은 미검증이다.
- 기간 지정 알림 쉬기·사건 확인 기한을 저장하고 재시작 후 복원한다. HA 서비스 `bapsim.set_notification_control`로 적용·취소하며, 가상 보조 활동은 `bapsim.record_simulated_activity`로만 넣는다. 보조 활동은 시뮬레이션 판단을 최대 2시간 미루며 실물 판단에 섞지 않는다.
- 정규화 관측은 `bapsim_observations/`에 90일, 사용 묶음·기준·판단·발송 기록은 `bapsim_records/`에 180일 보존한다. 원시 수신 저널은 별도이며 보존·백업 정책은 현장 운영에서 정해야 한다.
- HA MQTT 서비스가 연결돼 있으면 상태를 60초 주기로 QoS 1·retain으로 게시하고, 요약 센서 discovery 및 180초 만료를 제공한다. 시뮬레이션 토픽은 실물 토픽과 분리했다. 선택적 독립 Docker 작업자는 MQTT 구독·상태 게시·브로커 LWT를 제공한다.
- `python -m tools.simulate_notification_flow`로 실기기·실사용 기록·휴대폰 없이 7일 학습부터 연속 미사용, 알림 요청, 보호자 확인, 사용 재개 해결, 재시작 복원을 임시 파일에서 재현한다. 시뮬레이션 상태 토픽과 중복 요청 방지를 확인한다. 실제 HA·MQTT 전달이나 폰 수신의 증거는 아니다.
- 별도 [다조건 가상 학습 노트북](../ai/밥심_다조건_가상학습_Colab.ipynb)은 안정·늦은 사용·자연스러운 건너뜀·3일 간격 조리 조건으로 후보를 선택하고, 다른 가구의 점진적 시각 이동·주말 이동·복합 건너뜀 조건으로 평가한다. 설정 후보는 운영에 적용하지 않는다.
- 첫 안내가 성공한 공백은 다음 개인 예상 사용 창이 다시 누락될 때 별도 ID로 재안내한다. 불규칙 패턴은 학습한 사용 간격을 사용하고, 장기 감소는 7일 간격으로 재안내한다. 앞선 안내가 실제로 성공한 공백에서만 사용 재개를 한 번 안내한다. 사건·발송 횟수·다음 간격은 재시작 후 복원한다.
- 관측 단절은 생활 공백과 별도로 관리한다. 10분 지속 시 하루 한 번 연결 확인 안내 후보를 만들고, 야간 보류 중 복구되면 발송하지 않는다. 휴대폰 서비스 호출에 실패한 첫 안내는 성공으로 기록하지 않고, 유효기간 내 재시도가 성공하면 그때 발송 완료로 전환한다.
- 알림 ID별 발송 기록에 `pending`·`ha_accepted`·`failed`·`uncertain`·`cancelled`, 시도 횟수와 다음 재시각을 저장한다. 명확한 실패만 30초·2분·5분 뒤 재시도 대상으로 두고 실제 호출은 다음 60초 주기 평가에서 최대 세 번 더 실행한다. 호출 중 재시작이나 시간 초과처럼 결과가 불명확한 경우 같은 ID를 자동 재발송하지 않는다. 기록은 180일 뒤 정리한다.
- [SW 가상 검증 기록](SW_가상검증_2026-10-03.md)에 T08~T13·T17·T20의 합성 재생 결과와 로컬 Docker 재시작 점검을 구분해 남겼다. `python -m tools.run_software_matrix`로 시나리오별 JSON 증거를 다시 생성할 수 있다.
- [알림 가상 최적화 기록](알림_가상최적화_2026-10-03.md)에서 모델 내부 후보가 아닌 보호자 발송 요청을 8개 설정으로 비교했다. 훈련에서 선택된 후보는 별도 조건의 정상일 요청이 더 많아 운영값을 유지했다. 격일 사용 가구의 당일 발송 요청 누락이 남아 있다.
- [강건 가상 평가](강건_가상평가_2026-10-03.md)에서는 사용 시각·건너뜀·개방 신호 누락을 흔들고 생활 유형별 최악 손실로 설정을 골랐다. 선택 후보는 별도 복합 조건에서 기존 설정보다 나빠 운영값을 변경하지 않았다.

## 이번 구현에서 확인한 것

- Python 자동 테스트 **132개 통과**: 기존 개인화·HA 경로와 알림 재시도 간격, 불명확 결과의 재발송 중지, 재시작 복원, 가상 시나리오 흐름을 확인했다.
- 배포 ZIP은 `python -m tools.build_ha_bundle`로 생성하며 개인화 모델과 서비스 모듈을 통합 내부에 포함한다. 로컬 Docker에서 HA 2026.9.0, Mosquitto 2.0.22, 독립 분석 작업자를 실행했다. HA MQTT 통합을 `mosquitto:1883`에 연결하고 시뮬레이터 뚜껑 개방이 정규화 관측 → MQTT 작업자 → 별도 시뮬레이션 상태 토픽 → HA 대시보드까지 도달하는 것을 확인했다.
- 로컬 개발 브로커는 `127.0.0.1:1883` 바인딩과 익명 접속을 사용한다. 실물 환경용 브로커 인증·접근 제어는 별도다. 로컬 `.env`의 HA 알림 API 토큰으로 작업자의 HA API 인증과 시험용 로컬 알림을 확인했다. 토큰 값은 Git에 포함하지 않는다. 휴대폰 Companion 앱 서비스와 실제 푸시는 아직 설정·검증되지 않았다.

## 외부 입력이 있어야 검증할 것

1. 실제 Matter 접점의 HA 엔티티와 열림/닫힘 방향, 장시간 연결·단절·복구 기록.
2. 일주일 이상 이어진 실제 사용 데이터로 예상 시간·오경보·누락을 평가하고 초기 시간대·확률 기준·알림 횟수를 조정하는 일. 합성·단위 테스트는 실제 정확도를 입증하지 않는다.
3. 실제 Companion 앱 등록, 휴대폰 푸시 수신과 액션 응답.
4. 여러 사람이 같은 밥솥을 쓸 때의 식별 정책. 현재 모델은 사람 식별자가 아닌 `source + device_id`별로 학습한다.

센서 기록만으로 실제 식사 여부는 확정할 수 없다. 모델의 출력은 해당 밥솥의 **예상 사용 패턴에서 벗어난 정도**이며 건강 상태나 결식 판정이 아니다.
