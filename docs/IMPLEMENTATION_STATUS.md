# 구현·검증 결과와 한계

기준일: 2026-10-15. 구현, 소프트웨어 검증, 실제 설치와 현장 검증을 구분한다.

## 확인된 범위

| 대상 | 확인 내용 | 해석 범위 |
|---|---|---|
| 센서·통신 | 실제 개폐·광센서·온도 관측, Matter/HA 수신, 개발 시험 폰 알림 | 식사 확정이나 운영 개인화 검증이 아님 |
| 개인 분석 | 사용 묶음, 초기 자료 부족, 시간대/요일·간격·감소, 연결 공백 제외 | 자동 테스트와 합성 시나리오 |
| 알림·응답 | 중복 억제·야간 보류·확인·기간 보류·취소·복원 | 일부 실제 폰 확인과 나머지 소프트웨어 검증을 구분 |
| 저장·복원 | B 상태 사본 72파일과 격리 복원, 합성 활성 사건/발송 상태 검사 | 전체 HA OS/Matter Fabric 복원이 아님 |
| 최신 UI | 보호자 화면·생활 시간 설정·연결 시험 안내가 원격 main에 통합됨 | 현재 HA 설치본과 동일하다고 가정하지 않음 |

## AI를 두 부분으로 구분

보드의 결정트리는 운전 상태 후보를 추정하고 HA의 개인 모델은 사용 시각·간격의 변화를 분석한다. 합성 학습 보드 모델은 실물 일반화 성능이 검증된 제품 모델이 아니다. 실제 관측을 `test`에서 `live`로 바꾸어 개인 학습에 소급 편입하지 않는다.

개발 과정에서 취득 주기 이탈과 광센서의 주변광/인접 LED 간섭을 발견했다. 현재 +21 소스는 취득·처리 분리, 설치 프로필, 신뢰하지 않는 예약 채널 제외 및 기존 모델의 합의 판정을 포함한다. 기본 생성은 test이며, 명시적인 live 전송 옵션을 제공한다. +21 설치 후 실제 보온 상태의 HA 수신과 짧은 연속 취득 구간을 확인했다. 이는 취사·예약 전체 정확도나 장시간 안정성 검증이 아니다. 모델 적격 표시는 계속 false다.

보호자 커스텀 카드와 분리된 합성 재생은 HA에 배포했다. 공개 설치 ZIP에도 JS·JSON 및 리소스 등록 안내를 포함한다. 패키지 자동 검증은 별도 HA 신규 설치 성공을 의미하지 않는다. 합성 재생은 기존 분석/워크플로 결과를 보여주며 실제 알림 발송이나 운영 설정 변경을 수행하지 않는다.

기존 대기 83개·보온 121개 창 재생은 서로 중첩된 개발 자료다. 독립 시험 횟수나 전체 상태 정확도로 사용하지 않는다. 합성 생활 패턴 비교의 사건 포착 3/4 역시 실생활 사용자 성능으로 해석하지 않는다.

## 재현 방법

```sh
python -m unittest discover -s tests
python -m tools.prepare_demo
```

실행 당시 커밋·설정·입력 유형과 결과를 함께 보관한다. 테스트 개수는 소스 버전에 따라 달라지므로 과거 통과 개수를 현재 결과로 재사용하지 않는다. 준비 도구의 출력은 로컬 `local-data/`에 저장된다. 실제 장치 주소와 사용자 기록은 공개 증거에 넣지 않는다.

## 남은 범위

- 발표 장소의 HA/Nest/네트워크와 폰 화면·복구 순서 확인.
- 새 설치 환경의 보드·HA 버전 및 입력 매핑 대조, 현재 구성의 실제 휴대폰 수신·응답 확인.
- 취사 전반 정확도, 온도 절대 정확도·지연, 오류 주입, 24시간 안정성.
- 대상 사용자의 독립 라벨·기간을 갖춘 개인화 실측 평가와 운영 사건 응답 검증.
- 전체 HA/Matter 등록 정보 복원. 프로젝트 코드는 MIT로 공개 준비했으며 제3자 구성요소 고지는 별도로 유지한다.

추가 취사·센서 수집은 이번 문서·코드 공개 준비의 선행 조건이 아니다. 미검증 범위를 완료로 바꾸지 않고 발표 설명에 유지한다.
