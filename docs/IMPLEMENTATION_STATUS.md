# 밥심 구현 상태 — 2026-10-02

현재 저장소의 담당 범위는 Home Assistant(HA) 수신 이후다. Nordic 펌웨어·보드 Edge AI는 다른 담당자의 범위다. 이전 구현 기록은 [구현 점검](구현_점검_2026-10-02.md)에 남아 있다.

## 현재 소프트웨어

- 원시 8필드 이벤트 → 접점 상태 전이·단절 정규화 → [개인별 사용 패턴 모델](개인화_사용패턴_모델.md) → 알림 상태 관리. 모델은 일반 초기 시간대에서 시작해, 구간별로 연결이 확인된 과거 7일을 학습한 뒤 개인의 예상 시각과 사용 확률을 계속 갱신한다. 이전 하루 횟수 기준선과 `RuleDetector`는 활성 HA 판정에 사용하지 않는다.
- HA는 정규화된 뚜껑 개방만으로 모델을 학습할 수 있다. 취사 신호는 세션·특징 진단용으로 계속 받지만, 등록되지 않거나 끊겨도 접점 모델을 오프라인으로 만들지 않는다. 접점 단절, 외출, 학습 부족은 결측·보류 상태로 구분한다.
- 예상 구간의 개방 누락이 높은 확률로 판단되면 `check_required`를 낸다. 서로 다른 예상 구간에서 36시간 안에 연속 두 번 발생하면 보호자 사건을 만들고 HA 로컬 알림과 등록된 Companion 앱 서비스를 호출한다. 중복 알림 제한, 보호자 확인·완료 응답, 재시작 복원이 있다.
- `bapsim.set_away`로 부재를 선언·복원한다. 외출 중 관측되지 않은 개방은 학습하지 않으며 활성 사건은 해결 상태로 닫는다. 실패한 휴대폰 서비스 호출은 활성 사건에 한해 저장·재시도한다.
- HA Matter 접점·취사 엔티티를 원시 이벤트로 바꾸는 등록 서비스, 보드 관측·추정 신호의 원시 수신, 선택적 타 Matter 기기의 독립 원시 수신이 있다. 출처가 Matter가 아닌 엔티티는 거부한다. 추정 신호를 검증된 행동으로 자동 승격하지 않는다.
- HA 설정 폴더의 `bapsim_events/`에 원시 이벤트를 UTC 날짜별 JSONL로 계속 기록한다. 최근 1,000건 보드 신호는 HA 저장소에서도 빠르게 조회할 수 있다. JSONL의 백업·보존 기간·디스크 용량은 운영 환경에서 관리해야 한다.
- 취사 세션·24시간 특징·이전 일별 기준선/규칙과 Colab 가중치 후보 코드는 비교와 진단을 위해 남아 있다. 이전 가중치 후보는 현재 개인화 모델에 적용되지 않는다.

## 이번 구현에서 확인한 것

- Python 자동 테스트 **72개 통과**: 개인 시간대 이동, 첫 7일 보류, 평소 점심을 쓰지 않는 사람의 점심 이탈 비발생, 습관 변화 적응, 단절·외출 제외, 재시작 복원, 접점 단독 HA 수신부터 모델까지, 두 예상 구간 후 알림과 응답을 포함한다.
- 배포 ZIP은 `python -m tools.build_ha_bundle`로 생성하며 개인화 모델을 통합 내부에 포함한다. 기존 Docker 기반의 HA 설정 검사는 이전 버전에 대한 기록이다. 이번 변경은 현재 환경에 `docker` 명령이 없어 실제 HA 컨테이너 설정 검사·화면 확인을 수행하지 못했다.

## 외부 입력이 있어야 검증할 것

1. 실제 Matter 접점의 HA 엔티티와 열림/닫힘 방향, 장시간 연결·단절·복구 기록.
2. 일주일 이상 이어진 실제 사용 데이터로 예상 시간·오경보·누락을 평가하고 초기 시간대·확률 기준·알림 횟수를 조정하는 일. 합성·단위 테스트는 실제 정확도를 입증하지 않는다.
3. 실제 Companion 앱 등록, 휴대폰 푸시 수신과 액션 응답.
4. 여러 사람이 같은 밥솥을 쓸 때의 식별 정책. 현재 모델은 사람 식별자가 아닌 `source + device_id`별로 학습한다.

센서 기록만으로 실제 식사 여부는 확정할 수 없다. 모델의 출력은 해당 밥솥의 **예상 사용 패턴에서 벗어난 정도**이며 건강 상태나 결식 판정이 아니다.
