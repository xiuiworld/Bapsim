# 밥심 소프트웨어 구현 현황

밥심은 밥솥 사용 기록에서 개인별 예상 사용 시간과 사용 확률을 학습하고, 평소와 다른 사용 공백에 안부 확인 알림을 만드는 Home Assistant(HA) 통합이다. 센서 기록만으로 실제 식사 여부를 확정하지는 않는다. [상세 구현 상태](IMPLEMENTATION_STATUS.md)와 [개인화 모델](개인화_사용패턴_모델.md)을 참고한다.

## 현재 동작

1. 시뮬레이터 또는 Matter 접점에서 8필드 원시 이벤트를 받는다. 어댑터는 판단하지 않고 원시 상태만 전달한다.
2. HA 내부 정규화기가 접점의 실제 열린 전이를 `lid_opened`로 만든다. 처음 읽은 상태는 기준 상태로만 저장한다.
3. 로컬 개인화 모델이 약한 일반 시간대에서 시작해 접점이 정상 연결된 과거 7일을 학습한다. 이후 개인의 사용 시간과 요일별 확률을 계속 갱신한다. 접점 단절·외출은 사용하지 않은 날로 학습하지 않는다.
4. 확률이 높은 예상 구간에 개방이 없으면 `check_required`로 표시한다. 서로 다른 예상 구간에서 36시간 안에 연속 두 번 발생하면 보호자 사건을 만들고 HA 로컬 알림을 보낸다. 등록된 Companion 앱 대상이 있으면 휴대폰 서비스도 호출한다.
5. 보호자는 HA 화면이나 알림 액션으로 확인 중·안부 확인 완료를 기록할 수 있다. `bapsim.set_away`는 외출을 지정하거나 해제한다.

취사 입력은 실제 장비에서 시작·완료 의미가 검증되면 연결할 수 있다. 현재 개인화 알림에는 필수가 아니며, 취사 세션과 24시간 특징은 진단용이다. 보드의 LED·온도·추정값은 원시 관측과 추정으로 보존하고 검증된 취사 행동으로 자동 변환하지 않는다.

## 확인 상태와 남은 일

자동 테스트는 개인 시간대 이동, 학습 기간, 평소 점심을 사용하지 않는 사람, 습관 변화, 접점 단독 Matter 입력, 단절·외출, 알림·응답을 포함한다. 실제 Matter 센서 수신, 장기간 실사용 정확도, 휴대폰 푸시 수신은 아직 검증하지 않았다. 현재 환경에는 Docker 명령이 없어 이번 변경의 HA 컨테이너 설정 검사와 화면 확인도 수행하지 못했다.

실물 연결 전에는 [Matter 입력 연계 계약](밥솥_Matter_입력_연계_계약.md)에 따라 접점 엔티티와 열림 방향을 확인한다. 일주일 이상의 실사용 로그가 쌓이면 오경보와 누락을 살펴 초기 확률 및 알림 기준을 조정한다. 여러 사람이 같은 밥솥을 사용한다면 현재 모델은 사람별이 아니라 밥솥별 패턴을 학습한다.
