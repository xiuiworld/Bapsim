# 개인별 밥솥 사용 패턴 모델

상태: HA 수신 이후 소프트웨어에 연결됨. 실물 센서 데이터와 실제 식사 여부로 성능을 검증한 결과는 아직 없다.

## 입력과 실행 위치

`bapsim_raw_event` → `CookerEventNormalizer` → `lid_opened`/`device_online`/`device_offline` → `PersonalUsageModel` → `bapsim_detection_event` → 보호자 알림 상태 관리.

모델의 학습과 추론은 HA가 실행되는 노트북의 Python 코드에서 로컬로 처리한다. 모델 상태는 HA의 `.storage/bapsim.pipeline`에 저장해 재시작 후 복원한다. 원시 입력의 8필드 계약과 입력 어댑터에는 판정 로직을 넣지 않는다. 취사 세션·24시간 특징은 관측 진단용으로 유지하지만 활성 알림 판정에는 사용하지 않는다. 이전 `PersonalBaselineEngine`·`RuleDetector`도 활성 판정 경로에서 제외했다.

## 초기값에서 개인화까지

- 처음에는 08:00, 13:00, 19:00, 00:30(KST) 부근의 네 개 **약한 초기 사용 구간**을 둔다. 식사 시각의 사실이나 사용자별 정답이라는 뜻은 아니다. 구간의 초기 사용 확률은 각각 0.35, 0.45, 0.40, 0.10이며, 각 초기값은 개인 관측 약 2일에 해당하는 낮은 비중이다.
- 실제 뚜껑 개방 시각을 가장 가까운 구간에 묶어 구간의 중심 시각을 갱신한다. 구간은 중심 전후 2시간이다. 반복 개방은 첫 개방부터 60분 고정 창으로 한 사용 묶음에 넣는다. 원 개방 시각은 별도로 보존하며, 예상 사용 창 안에 실제 개방이 있었는지는 원 개방 기록으로 판단한다. 일별 감소 추세는 KST 날짜별 원 개방을 먼저 나눈 뒤 그날 안에서 60분씩 묶는다. 자정 이후 실제 활동이 전날 묶음 때문에 사라지지 않게 하려는 기준이며 끼니 수를 뜻하지 않는다.
- 각 구간에서 연결이 정상인 **이전 날짜 최소 7일**이 모이기 전에는 `learning`만 낸다. 7일은 학습 종료가 아니며, 이후 최근 28일 기록으로 계속 갱신한다.
- 구간의 사용 확률은 `(초기 확률 × 2 + 개인 사용일의 가중 합) / (2 + 개인 관측일의 가중 합)`에서 시작한다. 주중/주말과 같은 요일의 관측도 전체 개인 패턴과 섞어 표본 하나를 과신하지 않는다. `sensor.bapsim_baseline`의 `windows`에서 예상 시각, 사용 확률, 관측일 수, 개인 기록 비중을 볼 수 있다.

## 판정과 알림

예상 구간의 끝에 도달했을 때, 그 구간에 뚜껑 개방이 없고 개인 사용 확률이 0.72 이상이면 `check_required`를 낸다. 확률이 낮으면 `no_expectation`이며, 이를 한 끼의 결식으로 계산하지 않는다. 접점 연결이 구간 내내 확인되지 않거나 외출이 명시되어 있으면 각각 `data_unavailable`/`away`로 처리한다. 모델은 구간 하나를 한 번만 평가하므로 시간별 재평가로 같은 이탈을 중복 세지 않는다.

시간별 평가가 늦게 실행되면 최근 36시간 안에 끝난 예상 구간을 한 번씩 복구 평가한다. 실제 개방이 그 사이에 관측되었거나 구간의 연결 증거가 부족하면 지나간 미사용 알림 후보를 내지 않는다. 36시간보다 오래된 구간은 재생하지 않으며, 중단 중 관측되지 않은 사용을 추정하지 않는다.

모델은 마지막으로 수용한 개방 시각을 상태에 보존한다. 그보다 오래되거나 같은 시각의 개방이 뒤늦게 들어오면 학습 이력을 다시 쓰지 않는다. 최근 연결 확인 시각보다 36시간 이상 오래된 개방도 실시간 학습에서 제외한다. 실제 과거 자료를 일괄 재학습하려면 별도 시간순 재생 경로를 사용한다.

보호자 알림은 **서로 다른 예상 사용 구간에서 36시간 안에 연속 두 번** `check_required`가 나왔을 때 요청한다. 기대가 낮은 구간의 `no_expectation`은 이 연속성을 깨지 않으며, 실제 개방이 관측된 구간과 연결 단절·외출은 이를 초기화한다. 외출 선언은 활성 사건을 해결 상태로 만들고 대기 중인 휴대폰 재전송을 제거한다.

시계 시간대가 뚜렷하지 않은 가구는 사용 간격을 평가한다. 관측 간격 중앙값이 36시간 미만이면 경험적 95% 값을 사용한다. 36시간 이상인 드문 사용 패턴에는 로그 간격의 중앙값·MAD로 계산한 예측 90% 값과 경험적 95% 값 중 이른 쪽을 사용한다. 이는 합성 시나리오에서 두 지표가 함께 개선된 제한적 변경이며 실제 위험 확률을 뜻하지 않는다. 근거와 지연 측정은 [드문 사용 간격 가상 비교](드문_사용간격_가상비교_2026-10-04.md)에 기록했다.

이탈로 표시된 날짜는 이후 학습에서 0.15의 낮은 가중치로만 반영한다. 이 방식은 일시적 이탈이 곧바로 정상 기준을 바꾸는 것을 막으면서 장기간의 실제 습관 변화에는 천천히 적응한다.

## 해석 한계

- 모델이 배우는 대상은 **해당 밥솥의 사용 패턴**이다. `source + device_id`로 구분하므로 한 밥솥을 여러 사람이 함께 쓰면 사람별 패턴을 분리할 수 없다.
- 출력 확률은 현재 관측 모델의 추정치다. 실제 식사 여부나 건강 상태의 확률로 읽으면 안 된다. 식사 여부 모델을 만들려면 사용자 확인 등 별도의 정답 데이터가 필요하다.
- 현재 초깃값·구간 폭·확률 기준·알림 횟수는 제품 설정의 초기값이다. 실제 가구 기록으로 오경보·누락과 사용자 부담을 평가해 조정해야 한다.
- HA가 중단된 시간은 관측 가능 시간으로 채우지 않는다. 재시작 후 모델은 마지막 저장 시각에서 연결 구간을 닫고 현재 상태를 새로 읽는다. 접점이 아닌 취사 신호만 빠진 경우에는 뚜껑 기반 학습을 계속한다.
- 이전 일별 기준선은 새 모델의 입력 형식과 달라 자동 변환하지 않는다. 활성 모델은 새 정규화 이벤트가 쌓이면서 학습한다. 보관된 원시 JSONL은 추후 과거 이력 재처리의 자료가 될 수 있다.
