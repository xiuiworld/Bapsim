추가 도구 설치 없이 기존 SDK로 기본 예제를 검증한다. 보드는 SDK 문서가 안내하는 IMCU USB 경로로 연결한다.

## 실행 상태

- SDK 기본 `hello_world` 예제 빌드 성공 (종료 코드 0).
- 사용자가 현재 보드 프로그램을 기본 예제로 교체해도 된다고 확인했다.
- nrfutil runner로 플래시·이미지 검증·리셋 성공.
- 별도 소프트웨어 리셋 후 **COM8 / 115200 baud**에서 SDK 부팅 배너와 Hello World 확인. COM7에서는 출력이 없었다.
- 빌드 결과 메모리 사용: FLASH 31,984 B, RAM 6,024 B. 기본 예제 값이며 Matter/AI의 자원 사용량이 아니다.
- SDK 원본 예제를 사용하고 저장소 `firmware/`는 수정하지 않는다.
- 빌드 결과 위치: `%TEMP%\bapsim-a01-hello-20261004` (임시 파일로 추후 삭제될 수 있음).

## 재현 방법

SDK 3.4.1의 툴체인 환경이 설정된 터미널에서 실행한다. 일반 PowerShell에는 `west` 등이 없을 수 있다. 이번 검증에서는 툴체인의 `environment.json`에 정의된 환경변수를 해당 프로세스에만 적용했다.

```powershell
Set-Location C:\ncs\v3.4.1
west build -b nrf54lm20dk/nrf54lm20b/cpuapp C:\ncs\v3.4.1\zephyr\samples\hello_world -d "$env:TEMP\bapsim-a01-hello-20261004"
# 현재 장치 ID는 nrfutil device list로 확인한 뒤 지정한다.
# 아래 명령은 선택한 보드의 현재 프로그램을 교체한다.
west flash -d "$env:TEMP\bapsim-a01-hello-20261004" --no-rebuild --dev-id <장치_ID>
```

직렬 설정은 SDK 보드 정의 기준 115200 baud다. 이번 실제 콘솔은 COM8이었다. 기본 예제는 부팅 때 한 번 `Hello World!`를 출력하므로 로그 포트를 연 뒤 재부팅해 확인한다. pyserial에서 DTR/RTS를 활성화하고 두 포트를 확인했다.

실제로 수신한 로그:

```text
*** Booting nRF Connect SDK v3.4.1-b20f8619ba9a ***
*** Using Zephyr OS v4.4.2-33fa6a7aac6a ***
Hello World! nrf54lm20dk/nrf54lm20b/cpuapp
```

SDK 기본 설정에서 `NRF_PLATFORM_LUMOS` 사용 중단 예정 경고가 있었지만 빌드는 성공했다. 실제 실행 때 `--skip-rebuild` 별칭 사용 중단 경고도 있어 재현 명령은 권장되는 `--no-rebuild`로 기록했다.

## 완료 범위와 다음 단계

추가 설치 없이 개발 도구·보드 인식·기본 예제 빌드·설치·재부팅 실행 로그까지 검증했다. 후속 사용자 확인으로 보드 스티커의 하드웨어 리비전 `0.7.0`을 기록했다. HA 환경은 A02에서 HA OS VM 설치·기동과 대시보드 접속까지 확인했다. 현재 보드에는 Matter 펌웨어가 아닌 Hello World 기본 예제가 실행 중이다.

## 점검 중 발견 사항

Codex 샌드박스 안에서는 Windows 사양 조회와 nrfutil 실행이 제한됐고 `west build` 확장을 찾지 못했다. 같은 설치를 권한 확장 환경에서 실행하니 장치 조회와 빌드 구성 단계가 진행됐다. 이 오류만으로 SDK 재설치가 필요하다고 판단하지 않는다.

보드와 무관하게 Docker 엔진은 이번 조회에서 응답하지 않았다. A02에서 기존 HA 설치 위치·실행 방식을 확인한 뒤 환경을 준비한다.
