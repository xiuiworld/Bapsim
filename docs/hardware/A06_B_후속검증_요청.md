## 재현 환경

기존 HA OS 내부 분석 모드(`external_service` 미설정), 인증 Mosquitto 2.0.22, B 원본 simulator package와 lab dashboard를 사용했다. 논리 household는 `household_a_test`, simulator device는 `cooker_01`, A05 시험 보드는 `cooker_a_test`다. A는 분석/정규화/출력 코드를 수정하지 않았다.

## 수정 또는 계약 확인이 필요한 사항

1. **내부 분석 모드의 화면 출처 분리**: simulator의 통신 복구 → 닫힘 → 열림을 실행하면 `service/ha_analysis_flow.py`의 `show("output_state", ...)`가 실물 카드에 시험 결과를 표시한다. `simulation_output_state`는 생성되지 않아 실험실에 '엔티티를 찾을 수 없습니다'가 보인다. MQTT는 `bapsim/simulation/v1/...`로 올바르게 발행된다. 내부 분석 모드에서도 시험 전용 카드를 갱신하고 실물 화면에 영향을 주지 않는 회귀 검증이 필요하다.
2. **결과 만료와 기동 직후 표시**: `valid_until`은 발행 시각 +180초지만 내부 분석 모드 화면에서 이를 만료 처리하는 경로가 확인되지 않았다. MQTT discovery의 `expire_after: 180`은 Matter 출처에만 발행된다. 현재 A05 test 입력은 거부되므로 이 경로의 실기 검증이 불가능하다. 내부 모드의 소비자 만료 처리와 시험 출처로 검증할 수 있는 B 제공 경로가 필요하다. 재시작 직후 output 카드가 없고 mqtt_output=waiting인 과도 상태도 관측했다.
3. **시험/실물 저장 격리 수준**: 토픽과 모델 키는 출처로 분리되지만 HA의 `.storage/bapsim.pipeline`과 journal 루트는 공유한다. 공통 계약에서 물리적 저장소 격리가 필요한지 확정하고, 필요하면 B가 구현한다. A가 시험 데이터를 live로 바꾸거나 별도 정규화기를 만들지 않는다.
4. **전체 시험 경로**: A05 `input_kind=test`는 B live 입력에서 거부되고, B simulator는 실제 모바일 전송을 제외한다. 따라서 현재 두 경로 모두 보드 시험 입력→B→시험 전용 폰까지 이어지지 않는다. B가 시험 저장·알림 대상을 격리한 경로를 제공하거나, 지원되는 live 생산자가 준비된 후 통합 시험한다. A의 수동 폰 알림 수신/클릭 성공을 이 전체 경로의 성공으로 간주하지 않는다.
5. **폰 대상 서비스 설명**: 서비스 설명은 `notify.mobile_app_*`를 안내하지만 `set_notification_target` 구현은 `mobile_app_*`만 받는다. 전체 이름으로 호출하면 Unknown error, `mobile_app_nothing_phone_4a`로 호출하면 오류 없이 완료됐다. 설명과 입력 검증 형식을 맞춰야 한다.

## A가 확인한 범위

- 인증 MQTT 연결, simulator retained 상태 수신, 끊김 표시와 복구.
- 수동 알림의 실제 Nothing Phone (4a) 수신 및 `/bapsim-lab/status` 이동(사용자 스크린샷).
- HA Core 재시작 후 뚜껑 열림 1회와 online helper 유지.
- B 오프라인 시나리오 실행 성공: resolved 상태가 재시작 후 유지, real_push_sent=false. 실제 HA/폰 시험과 별도다.
- 관측 보존 경계·결과 만료 값/출처별 토픽 관련 기존 단위 테스트 3개 통과. 장기간 실제 저장소 삭제나 화면 만료의 증거는 아니다.

상세 백업·복구 결과는 [A06 배포 검증](A06_HA_OS_배포_검증.md)에 기록한다. 이 문서는 전달용 초안이며 팀원에게 자동 발송하지 않았다.
