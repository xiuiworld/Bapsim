# A05 합의된 데이터 모델 구현·HA 노출

2026-10-04 · 진행 중 · 기존 A04-2를 A05로 변경했다.

## 기준과 현재 결과

[Matter·HA 명세](../contracts/Matter_HA_연동_명세.md)와 [A–B 계약](../contracts/AB_데이터_계약.md)의 의미를 유지한다. 보드의 Matter 인코딩, HA 노출, B의 JSON 정규화는 서로 다른 단계다. 이 문서의 이름 기반 Snapshot 예시는 **오프라인 구현 후보**이며 Matter 전송 JSON이나 실제 수신 기록이 아니다.

전체 필드 대응표에 이어 SnapshotPacked v1 데이터 모델 생성·빌드·앱 영역 플래시·HA 수신 코드 배포를 수행했다. 현재 장치는 A05 시험 이미지이며 **실제 센서·AI 출력은 아니다**. 아래 최초 대응표의 미구현 표시는 착수 당시 상태이고, 현재 결과는 뒤의 실행 기록을 따른다. B 서비스 호환성은 아직 해결되지 않았다.

## 구현 후보와 검증 경계

공통 명세의 단일 Snapshot 구조체 방향을 우선 검토한다. SDK 생성기와 설치된 Matter Server가 제조사 구조체를 어떤 형태로 전달하는지 검증한 다음 ID·필드 태그·최대 길이를 확정한다. A04의 카운터 int 읽기 성공만으로 구조체 지원을 단정하지 않는다. A04 ID는 시험 예제용이며 제품 ID로 확정하지 않았다.

LidOpen/TemperatureCentiC는 동일 시점 품질과 대응시키기 위해 이름 기반 후보 Snapshot에 포함했다. 표준 속성과 함께 제공할 때의 원자적 갱신/이벤트 처리는 아직 구현 전이다. 모델 점수·품질의 조합 검사는 후보의 엄격한 수신 규칙이며 기존 공통 계약을 몰래 개정하지 않는다. 실제 전송에서 다른 null 표현이 필요하면 디코딩 경계에서 명시적으로 대응시킨다.

`tools/a05_contract/validate_snapshot.py`는 이름 기반 원시 객체의 완전성·타입·범위·품질·추정 provenance를 검사한다. 정상 객체를 변경하지 않으며 B 관측 JSON 생성, AI, 보정, 네트워크 연결, HA 상태 쓰기를 하지 않는다. BootId 변화/순번 공백의 시간적 판단, Matter TLV 디코딩, 구독 처리는 아직 없다.

시험 자료 `snapshots.test.json`은 취사 후보→보온 후보→센서 오류/판단 불가→재부팅/미지원의 4개 **수작업 시험 입력**이다. 실제 AI 출력·학습 데이터·보드 캡처가 아니다. 점수는 null이며 시험 버전을 명시했다.

```powershell
python tools/a05_contract/validate_snapshot.py tools/a05_contract/snapshots.test.json
python -m unittest discover -s tools/a05_contract -p 'test_*.py' -v
```

2026-10-04 실행: 4개 후보 Snapshot 검사 및 5개 테스트 통과. 누락 필드, 잘못된 enum/버전, bool을 카운터로 사용, 범위 초과, 오래된 정상값을 오류 품질에 붙이는 경우를 거부하고 실제 0°C는 허용함을 확인했다. 오프라인 테스트이며 HA/보드 실기 성공은 아니다.

## 착수 당시 구현 순서와 현재 판정

1. 완료: SDK의 속성 생성 경로를 검토하고 아래 SnapshotPacked 형식을 선택했다. 보드→서버→HA 디코딩을 확인했다. `firmware/`는 수정하지 않았다.
2. 완료: 확장 주소·바이트 배치·일관성/보고 방식을 기록하고 장치 시험 모델과 HA 수신 코드를 연결했다.
3. 부분 완료: 4개 시험 시나리오와 단절/복구를 확인했다. 물리 버튼 반복의 보드 기록과 HA 상태 이력 비교도 완료했다(아래 추가 기록).
4. B 입력의 `snapshot`은 현재 숫자 카운터 신호명이며 이 문서의 복합 Snapshot 자체를 그 숫자 상태에 넣지 않는다. B의 `platform == matter` 출처 검사와 전용 통합의 불일치를 해결할 호환 방식을 담당 범위에 맞춰 확인한다. 플랫폼 위장이나 출처 검사 해제는 하지 않는다.
5. 인계 자료 작성 완료. B의 확장 출처 수용 경로는 미해결이며 전체 단계가 끝나기 전 A05 완료로 표시하지 않는다.

## 2026-10-04 물리 버튼·빠른 반복 시험

사용자가 보드의 Button 1을 직접 조작했다. RESET이나 HA 상태 강제 설정을 사용하지 않았다. 같은 BootId=1920897178에서 UART 버튼 로그와 직후 SnapshotPacked 바이트를 디코딩하고, HA 히스토리 화면에서 `sensor.a05_lidopen`만 선택해 내려받은 CSV를 비교했다.

| 구간 | 보드 누름/놓기 변화 | HA에 기록된 상태 변화 | HA 이력에 남지 않은 중간 변화 |
|---|---:|---:|---:|
| 한 번 누른 채 유지 후 놓기 | 2 | 2 | 0 |
| 5회 수동 반복 | 10 | 2 | 8 |
| 10회 빠른 수동 반복 | 20 | 2 | 18 |

- 처음 누름은 HA `LidOpen=False`, 놓기는 `True`로 확인했다. 공식 Matter 문 엔티티도 놓은 뒤 `on`(열림)이었다. 유지 시간은 보드 UptimeMs 기준 39.965초다.
- 5회 구간의 실제 인접 변화 간격은 **0.602~1.777초**, 10회 구간은 **0.185~1.144초**였다. 안내한 3초/1초를 정확히 지킨 정시 시험으로 기록하지 않는다. 사용자가 간격이 대략적임을 알렸으며 재시험 없이 실제 기록으로 판정했다.
- HA CSV의 변화 시각(KST)은 단일 조작 18:46:17.413/18:46:57.362, 5회 구간 18:48:18.494/18:48:23.280, 10회 구간 18:49:46.307/18:49:51.340이다. 각 구간 False→True 1쌍만 남았다. 마지막 놓기 상태는 복구됐다.
- 보드에는 총 16회 누름·16회 놓기가 교대로 기록됐고, 각 버튼 직후 디코딩한 LidOpen의 방향이 모두 일치했다. 버튼 로그에 추가 변화는 없었다. HA 상태 이력에 추가/중복 전이는 없지만, CSV는 상태 변화 기록이므로 동일값 재수신이나 전송 패킷 중복 유무를 판정하지 않는다.
- HA 속성 `last_discontinuity=gap`도 실제 확인했다. 15초 주기 Snapshot 역시 순번을 증가시키므로 순번 차이를 버튼 누락 횟수로 계산하지 않았다.
- 위 누락 수는 **보드 버튼 변화 대비 HA 상태 이력에 보존되지 않은 변화**다. 무선 패킷 손실률이 아니다. 현재 5초 최신값 읽기에는 짧은 중간 상태를 복원할 기능이 없으므로, 현재값 확인은 성공했지만 모든 개폐 이벤트 보존 요구에는 미달한다. 실제 개폐 횟수가 필요한 경로는 추후 구독/이벤트 보존 방식으로 별도 검증해야 한다.
