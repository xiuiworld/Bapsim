## 완료 결과

- 합성 3분 발췌 시계열 **3,000개**, 20Hz 원시 행 **10,800,000개**, 2초 간격 특징 창 **183,000개** 생성. NPZ 원시 파일 합계 90,596,101 bytes(약 86.4MiB). 150시간 분량의 합성 발췌이지 실제 150시간 관측이나 3,000회 완전 취사 이력이 아니다.

- LED/NTC/개폐·시간/순번/부팅 경계 처리와 JSONL 기록/재생, 실측 라벨 import 및 동일 학습 명령, 작은 결정트리와 보류 가능한 규칙 기준선을 구현했다.
- 검증 테스트 **13개 통과**. 예제 원시 3,600행 기록→재생에서 61개 특징/valid 값이 생성 때와 완전히 같았다. 원시 3,000파일의 manifest SHA256을 대조했다.
- 학습 결과: 깊이 제한 6, **63노드**, **11개 특징**, validation에서 선택한 점수 기준 **0.9**. 점수는 학습 leaf 빈도이고 실제 사용 확률/정확도 보장이 아니다.

모든 수치는 생성 가정 안에서 얻은 값이다. 겹치는 창을 독립 표본으로 취급한 신뢰구간이나 실물 정확도 주장은 하지 않는다. 최종 test/stress 결과를 기준으로 이번 임계값을 재조정하지 않았다.

### 모델 크기와 보드 여유

- 개선 후보 ARM 객체: text+상수 **3,048 B**, 정적 data/bss=0. 소프트웨어 float 비교 보조 함수까지 링크한 모델 전용 ELF: text+상수 **3,328 B**. 기존 A05 `.config`에서 FPU 미사용을 확인했다. 모델은 신경망 런타임이나 NPU를 요구하지 않는 작은 트리다.
- GCC `-fstack-usage`의 추론 래퍼 자체 프레임은 **32 B**. 호출하는 보조 함수의 최대 중첩 스택이나 전처리 스택은 포함하지 않는다. ELF의 별도 `.stack` 4,096 B는 기본 링커가 예약한 값으로 실제 측정 스택 사용량이 아니다.
- 모델 입력은 11개 float32(44 B)와 valid, score 출력이다. 트리 상수는 읽기 전용 영역에 놓이고 힙 할당하지 않는다. 전체 합성 데이터/훈련 코드/NumPy를 보드에 넣는 구조가 아니다.
- 실제 A05 빌드 기록 `local-data/a05/build.log`: 앱 FLASH **755,728 / 1,949,552 B**, RAM **172,764 / 523,264 B**. 빌드 정적 여유는 각각 **1,193,824 B**, **350,500 B**다. SDK 보드 YAML의 범용 flash 숫자보다 실제 빌드 partition/map을 근거로 삼았다. 전체 SoC는 Nordic 데이터시트의 2036 KB NVM/512 KB RAM이다.
- 60초×20Hz×5채널의 uint16 원시 ADC 버퍼도 12,000 B지만 이것은 예산 산술 예시일 뿐 구현한 보드 버퍼가 아니다. 시간·상태·품질·전처리와 Matter 스레드/스택/힙까지 최종 합산해야 한다.
- **판단:** 모델 자체는 충분히 작은 후보이며 현재 정적 빌드 여유와 비교해 용량 부담이 작다. 최종 Matter 통합 링크·실제 최대 RAM/추론 시간·보드 실행/PC 대조는 아직 미검증이다. 기존 펌웨어를 플래시하거나 보드가 실행 중인 것처럼 기록하지 않았다.

## 원시 전처리 이식·실기 대조 후속 완료 — 2026-10-05

위 모델 단독 시험 다음으로 `preprocess.hpp`의 스트리밍 전처리를 실제 보드에 올렸다. 전처리 버전은 `a07-preprocess-v1`, 모델은 동일한 `a07-refined-v1-b1673351122b`다. 코드·재생 생성기·독립 PC 기대값·로그 판정기는 모두 `tools/a07_edge/`에 있다. A05 임시 앱에 시험 스레드만 추가했으며 `firmware/`와 B 코드는 그대로다.

구현은 최근 1,200표본 고정 링 버퍼, 20Hz 광센서 보정/히스테리시스, 최근 2초 점등 비율/전환 수, 50ms 접점 debounce, 1Hz NTC 변환과 60초 기울기다. 입력 시각·순번·부팅 ID를 검사하고 필수 입력 오류/불연속이면 모델을 보류한다. 연속 60초 이력이 복구되면 다시 판단 가능해진다. 품질 오류가 있는 채널 때문에 다른 정상 LED 관측을 지우지 않는다. 힙 할당을 사용하지 않는다.

### 비교 범위와 결과

정상 온도 상승, 보온, 냉각, 점멸/접점 bounce, 광센서 극성 반전, 초기 이력 부족, LED 누락/레일값, NTC 누락/레일값, 접점 누락, 시간 공백, 순번 공백, 부팅 ID/시각 초기화, 히스테리시스/점등 비율 경계, NTC 분압 방향 반전의 **14가지**를 시험했다. 각 시나리오 입력을 PC `observations.extract`에 먼저 넣고 그 결과를 보드의 C++ 결과와 대조했다. 실제 밥솥 기록으로 분류 정확도를 평가한 것이 아니다.

| 확인 항목 | 결과 |
|---|---:|
| 합성 원시 표본 | 33,959개 |
| 완성된 특징 창 | 442개; 이력 부족 시나리오는 0개 출력 |
| 특징값 불일치 | 0; 허용 오차 `2e-5 + 2e-6*abs(expected)` |
| valid / LED enum / 모델 판정 불일치 | 모두 0 |
| 모델 점수 불일치 | 0; 허용 오차 1e-6 |
| 전처리 고정 상태 | 28,952 B |
| 창 완성 호출 평균 / 관측 최대 | 1.883721 ms / 2.265 ms |
| 시험 스레드 스택 관측 사용 / 예약 | 1,672 / 4,096 B |
| 전체 앱 FLASH | 1,669,496 / 1,949,552 B (85.63%) |
| 전체 앱 정적 RAM | 209,308 / 523,264 B (40.00%) |

FLASH에는 원시 표본 배열 815,016 B와 기대값 배열 26,580 B, 이전 모델 단독 시험 벡터도 들어 있다. 이 검증 전용 배열은 실제 센서 배포에 필요하지 않다. 모델/전처리 실행에 1.67MB 자체가 필요하다는 뜻이 아니다. 전처리 시간은 창을 완성하는 push 호출만 측정한 것으로 직전 39개 표본 처리·ADC 취득·Matter 전송 시간은 합산하지 않았다. 실제 주기/최대 부하와 Matter 전체 동적 메모리는 A08 이후 확인한다.

```text
A07 RAW BEGIN version=a07-preprocess-v1 state_bytes=28952 model=a07-refined-v1-b1673351122b
A07 RAW END cases=14 windows=442 failures=0 window_mean_ns=1883721 window_max_ns=2265000 stack_rc=0 unused=2424
```

기존 모델 단독 1,000벡터 시험도 재부팅 후 불일치 0으로 통과했다. PC 테스트 14개가 통과했고, 로그 판정기로 14개 시나리오의 이름·창 개수·오류 개수·최종 요약을 자동 확인했다. 검증 결과와 로그 SHA-256은 `local-data/a07/raw-board/verification.json`에 남겼다.

### 플래시와 HA 유지

새 signed HEX의 범위 `[0xd000, 0x1a4a48)`가 앱 슬롯 안임을 확인하고 앱만 플래시했다. 복구용 이전 이미지는 `local-data/a07/board/a07-model-test.signed.hex`에 보존돼 있다. HA에서 기존 Node 4/entry를 통해 BootId `3965833315`, ReportCounter **4→10**, `input_kind=test`, `continuity=continuous`를 확인했다. 재등록이나 HA 서버 재시작 없이 수신했다.

현재 이미지: `local-data/a07/raw-board/a07-raw-test.signed.hex`, SHA-256 `28EE5263CB0307AC7122E5912E00207ED508B85F71FF14D5E46B2B359625DB86`. 같은 폴더에 `build.log`, `flash.log`, `boot.log`, `manifest.json`, `verification.json`이 있다. 대용량 시험 파일은 Git 제외다.

**최신 완료 범위:** A07의 센서 도착 전 원시 재생→전처리→모델 추론→PC/보드 대조 준비는 완료했다. 부팅 후 한 번 합성 원시값을 빠르게 재생하는 시험이며 물리 센서 ADC 드라이버·실시간 표본 취득·실측 보정·실제 모델 결과의 Matter 발행은 아직 연결하지 않았다. HA의 A05 값은 계속 별도 시험 fixture다. 다음 작업은 A08의 센서 취득·배선·보정, 이후 A09/A10의 실측 학습/평가와 실제 추론 전송이다.
