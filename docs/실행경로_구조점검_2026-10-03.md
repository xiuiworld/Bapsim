# HA 내부 모드·독립 작업자 실행 경로 점검

두 모드는 같은 `PersonalUsageModel`과 `DetectionStateManager`를 사용하지만, 평가 순서와 시뮬레이션 정책을 각 호스트에서 조립한다. 이 차이는 새 기능을 한쪽에만 넣기 쉽게 만든다. 저장소의 역할 분리는 유지하고, 우선 다음 경계를 공통화했다.

- `service.analysis_policy.assess_personal_use`가 예상 사용 창·불규칙 간격·장기 감소를 같은 순서로 평가한다. HA는 이벤트·센서·기록을 게시하고, 작업자는 MQTT 상태와 알림을 게시한다.
- `bapsim.record_simulated_activity`가 독립 작업자 모드에서도 시뮬레이션 전용 MQTT 토픽으로 전달된다. 작업자는 동일한 `AuxiliaryDeferral`을 사용하고 보류 상태를 재시작 후 복원한다. 실물 Matter 이벤트에는 보조 활동을 적용하지 않는다.
- `DetectionStateManager.current_state`와 `PersonalUsageModel.grouped_open_times`를 추가해 현재 화면·기록 생성에서 저장용 `dump_state()` 구조를 직접 검색하지 않게 했다.
- 같은 정규화 관측을 두 모드에 입력하는 회귀 테스트에서 첫 예상 사용 누락의 알림 후보 상태를 대조한다.

이 정리는 전체 알림 전달 코드를 하나로 합친 것은 아니다. HA의 비동기 Companion 서비스 호출과 작업자의 동기 MQTT·HA API 호출은 여전히 별도 어댑터이며, 조용한 시간 해제·재시도·확인 응답의 교차 모드 계약 테스트를 넓힐 여지가 있다. HA `__init__.py`에는 Matter 등록, 화면 출력, 저장과 서비스 연결이 여전히 집중돼 있다. 이 부분은 동작 보존 테스트를 먼저 확장한 뒤 기능별 모듈로 이동하는 게 안전하다.
